- Five building blocks of computers
	- 1) Processor
		- CPU
			- ALU
				- Does the *arithmetic* at the core of the computer
				- One chip of a few centimetres
				- *Billions* of transistors
				- Speed depends on
					- *Number* of *cores*
						- Each core has its own unit, ALU and registers, each running its own cycle
					- *Clock speed* of those cores (GHz)
						- 1 GHz = 1 billion cycles per second
				- Gets really hot (cooler is needed)
			- Control unit
				- Determines *order* of instructions
		- GPU
			- Second *processor* that is *specialised* for rendering graphics
			- Composed of *thousands* of *simple* cores that all do *small* calculations, needed for millions of pixels
			- Also used for editing videos and running simulations
			- Types
				- Dedicated
					- Own slot on motherboard
					- Own memory (VRAM) 
					- Own cooler
				- Integrated
					- Built into the CPU
					- Uses the same RAM
	- BUS
		- 2) Memory (RAM)
			- Holds the programs that are *running* and the data they need
				- Ex. words in a text document (that hasn't been saved)
			- About a *thousand* times *faster* than an **SSD**
			- Everything on the **RAM** *disappears* when power is cut
			- Location
				- Slots right of the CPU
				- Often soldered on in laptops
			- Usually 8GBs to 32GBs
		- 3) Storage
			- *Stores* data even when *power* is *cut*
			- Necessary for 
				- Operating system
				- Programs
				- Files
			- Types
				- Hard disk (HDD)
					- Spinning magnetic circular plates
					- Cheap
					- Slow, mechanical, prone to corruption and *outdated*
				- SSD
					- Flash memory chips
					- No moving parts
					- Much faster, smaller and more *modern* than HDD
			- A program will be copied from *storage* into *RAM* *before* it can run
		- 4) Input
			- Brings data from outside the computer into it
				- Converts something *physical* into *bits*
			- *Connected* to the computer in some way
				- USB
				- Wireless
				- Built-in
			- Common examples
				- Keyboard, mouse, touchscreen, microphone
			- Sensor examples
				- Temperature
				- GPS
				- Fingerprint reader
				- Motion sensor
		- 5) Output
			- Brings data from inside the computer to the outside
				- Converts *bits* into something *physical*
			- Examples
				- Screen, speaker, printer, LED, motor in robot, vibration motor in phone
			- Some devices do input and output at the same time
				- Touchscreen, headset, network card
		- (6?) Bus
			- Motherboard
			- All parts are connected to the *motherboard*, which serves as a *highway* for the *data sent* by all connected parts
			- By having all parts be connected *close* together, signal travel time is *minimized*
- From Switch to Chip
	- Transistor
		- Computers calculate with on (1) and off (0)
		- Transistors can be turned on (state = 1) or off (state = 0)
	- Computer chip
		- Thousands, millions or billions of transistors packed together
			- Moore's law used to state that every *two years* the *amount* of *transistors* on a chip would *double*
			- This rate is *slowing* down
		- Process
			- Sand -> Ingot -> Wafer -> Patterned Wafer -> Chip
- The Processor
	- Instructions
		- Program is *list* of *instructions* stored in memory/ RAM
		- Processor works through them one by one
		- For each instruction:
			- Fetch
				- Get the next instruction from memory
				- Read instructions at the address in the **program counter**
			- Decode
				- Work out what instruction means
				- Control unit reads the bits in the **instruction register**
			- Execute
				- Execute the instruction
				- The ALU computes with registers, or a value moves between a register and RAM, or the PC gets a new value: a jump
	- Registers
		- Memory of the CPU itself
			- +- 300 times faster than RAM
				- 300 cycles wait for one RAM request
		- Types
			- General purpose
				- R0, R1, …
				- The numbers being computed with
				- Part of ALU
			- Program counter
				- PC
				- Address of the next instruction
				- Part of control unit
			- Instruction register
				- IR
				- The instruction just fetched
				- Part of control unit
		- 64-bit processor = general registers are 64 bits wide
		- x86 = general registers are 16 bits wide
		- ARM = general registers are 31 bits wide
	- Complete instruction set:

| Machine code | Assembly       | Meaning                                  |
| ------------ | -------------- | ---------------------------------------- |
| 1x aa        | LOAD Rx, [aa]  | copy the value at address aa into RX     |
| 2x aa        | STORE Rx, [aa] | copy Rx to address aa                    |
| 3x nn        | MOV Rx, nn     | put the number nn in RX                  |
| 4x 0y        | ADD Rx, Ry     | Rx <- Rx + Ry (Z = 1 if the result is 0) |
| 5x 0y        | SUB Rx, Ry     | Rx <- Rx - Ry (Z = 1 if the result is 0) |
| 60 aa        | JMP aa         | jump: set the PC to aa                   |
| 70 aa        | JNZ aa         | jump to aa, but only if Z = 0            |
| 00 00        | HALT           | stop                                     |
- Processor: Continued
	- Jumps 
		- How a processor *makes decisions* and *repeats* steps
		- Jump instruction *overwrites* the program counter
	- Starting a program
		- On storage
			- Program is stored as a file in the SSD
		- Into RAM
			- The OS copies the program and its data into RAM
		- Set the PC
			- The OS sets the PC to the first instruction
		- Run
			- Fetch, decode and execute are continuously run
			- PC moves on or is changed with jump
	- More cores vs faster core
		- More cores only help if the work can be split up
	- Other Instruction Sets
		- x86
			- Used by Intel and AMD: in most desktops and laptops
			- Assembly
				- add eax
				- abx
			- Machine code (hex)
				- 01 D8
		- ARM (64-bit)
			- Smartphones, Raspberry Pi, Apple M-series
			- Assembly
				- add w0
				- w0
				- w1
			- Machine code (hex)
				- 00 00 01 0B
		- If an ARM processor receives the x86 bytes 01 D8 it will not be able to find a valid instruction resulting in the program crashing
