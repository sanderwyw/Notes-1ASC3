	- ROM
		- Memory that *can't* be written to
		- Used for BIOS and UEFI
			- Prevents them from being tampered with by malware
	- Hard disks
		- Composition
			- The hard disk is composed of a disc or *platter* and an *arm* that connects the *head* to the *actuator*.
				- The *disc* contains all of the *data* in the form of magnetic charges and spins at roughly 6000RPM
				- The *head* hangs a few nm above the disc and *writes* data to it
				- The *actuator* is connected to the device's motherboard and receives signals to move the head to a certain part of the disc
				- Dust can be incredibly *dangerous* to a hard disk, as even a *small* dust particle is *gigantic* compares to the distance between the head and the platter
		- Storage method
			- The hard disk is composed of several *tracks* that are again divided into *cells* that can either be magnetised *upwards* or *downwards*
			- If two cells next to eachother are *identical*, it will be read as a **0**
			- If two cells next to eachother are *different*, it will be read as **1**
			- For writing, the head will flip the cell *under* it
		- Tracks, sectors and cylinders
			- Track
				- Ring on the disc (not a spiral, arm jumps from track to track)
				- More sectors can fit on the *outer edges* of the disc, resulting in read speed being *faster* on the *outer* rings compared to the *centre* rings
			- Sector
				- *Vertical* line on the disc (90 degree difference to Track)
			- Sector
				- Small piece of connected data on a ring
				- Composition
					- Gap
					- Sync + Address
						- Allows the *head* to check the sectors location via its *sector number*
					- Data
						- 4096 bytes
						- A file of 5000 bytes will use 2 whole sectors
					- ECC
						- Extra bits to *detect* and *repair* small read *errors*
					- Gap
						- Space between two different sectors to make them more distinct from eachother
		- Reading a file
			- 1) Seek
				- Move the arm to the right track
				- ~8.5ms
			- 2) Rotational latency (wait)
				- Wait until the sector passes under the head
				- ~4.2 ms
			- 3) Transfer
				- Read the sector as it flies past
				- <0.1ms
			- Total =~ 12.7ms per random read
				- About 80 per second
		- Fragmentation
			- Defragmented
				- Files are written in sequence (as on a hard disc)
				- One small piece of the sector can be attributed to one file
			- Fragmented
				- Files are written sporadically (typically on a SSD)
				- Due to there not being an arm, every fragment can be accessed at the same speed.
	- SSD
		- Storage method
			- An insulated layer inside the transistor traps electrons. 
			- They stay for years without power. 
			- *Amount of charge* = *value*
			- Types
				- SLC
					- 1 bit per cell
					- 2 levels
					- Highest endurance
				- TLC
					- 3 bits per cell
					- 8 levels
					- Found in most SSDs
				- QLC
					- 4 bits per cell
					- 16 levels
					- Lowest endurance
				- Higher levels are cheaper per GB but read slower and wear out sooner
		- Composition
			- Connector
				- Is connected to the motherboard and transfers data
				- Connected via PCIe
			- Controller
				- Small processor that manages the SSD
			- DRAM cache
				- Cache for the SSD's controller processor to use
			- NAND grid
				- Grid on which data is stored
				- Won't go into depth here due to redundancy with things I wrote earlier in these notes
			- Fast due to
				- No moving parts
				- Many chips can be read in parallel
				- Easy to build layers upon layers of chips as with 3D flash
		- Pages, blocks and wear
			- Page = ~16KB
				- SSD only writes per page into an empty page
			- Block = several MB
				- SSD can only erase a whole block at once
			- Changing file locations
				- File is written to a new page, old one is marked invalid to be cleaned up later
