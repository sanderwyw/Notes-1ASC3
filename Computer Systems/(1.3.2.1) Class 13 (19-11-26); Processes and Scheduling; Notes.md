- Processes
	- Program
		- A file in your *storage*
		- *Static*, does nothing by itself unless *executed*
	- Process
		- A program that is *currently running*
		- Has been loaded into *RAM*, has its own *memory* and *CPU time*
		- A program can have *several* processes running at the *same* time
			- Such as several instances of Firefox
			- Each process has its own **PID** (process ID)
	- Process control block (PCB)
		- A PCB stores where along the process a program was
			- Program counter, registers..
		- OS keeps *one* PCB *per process*
		- This allows the OS to *stop* a process at *any* moment and to later *continue* it at the *same* point 
	- Managing multiple processes simultaneously
		- The CPU can only focus on *one process* at a time, but a device can have *hundreds* of processes running at the *same time*
- States and Interrupts
	- Important Terminology
		- I/O
			- Input and output
			- Everything located *outside* the CPU
				- Keyboard, storage, network..
			- *Very slow* compared to CPU
				- One disk read = millions of CPU steps
			- While I/O is active, the process *waits* while the CPU *switches focus*
		- Scheduler
			- Determines which program should *receive* the CPU *next*
			- Part of the Kernel
			- Picks a process from the *ready queue*
			- Runs every time a process *stops*, *waits* or its *time is up*
		- Timer
			- *Continuously* sets a clock that takes a *few milliseconds* that *switches* the CPU's focus when it *goes off*
	- Process States
		- New
			- The process has *just* been *created*
			- Soon switches to Ready
		- Ready
			- *Ready* to be *picked up* by the CPU
			- Waits for the CPU
			- Switches to Running after getting CPU focus
		- Running
			- *Currently being ran* on the CPU
			- Switches back to Ready after CPU switches focus
			- If the process was run to completion, it will switch to Terminated
		- Waiting
			- *Waits* for a *response* from I/O
			- Waiting to return data from RAM, storage, an input..
			- After the response has been received, it will switch to Ready
		- Terminated
			- The process is *finished*
		- An active program will oscillate between Ready and Running, and will switch to Waiting if needs data from I/O
	- Context Switch
		- The CPU *stops* one process and *continues* with another
			- Whenever a *timer goes off* or the process has to *wait for I/O*, a *context switch happens*
		- Takes only a *few nanoseconds*
		- Results in the *second* process starting *seamlessly* and then switching back to the *first* process *where it left off*
	- Interrupts
		- An interrupt stops the CPU immediately
			- The process' state is saved
			- Interrupt handler (piece of kernel code) is run
			- CPU continues
		- Types
			- Hardware interrupts
				- From outside the CPU
				- Examples
					- A key is pressed
					- The disk has finished reading
					- A network packet arrives
					- The timer fires
			- Software interrupts
				- From inside the running program
				- Examples
					- System call: the program asks the kernel how to proceed
					- Error such as division by zero
					- Trying to access unauthorised memory
			- Timer interrupts
				- From within the CPU itself
				- The timer *runs out*, the process is *ended* and the next one *starts*
				- Without timer
					- If there wasn't a timer, one looping process could keep the CPU occupied forever, freezing the entire computer
	- Ready Queue
		- List of all the next processes that the CPU must pick up
		- Works as a line; the first item in the list will be executed and will then be moved to the back
