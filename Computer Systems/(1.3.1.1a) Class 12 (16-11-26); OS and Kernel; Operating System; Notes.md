- Operating System
	- Purpose
		- An operating serves as the layer that *manages* the *hardware* upon which the *applications* run and are built.
			- Every program gets a *simple*, *standardized* way of *interacting* with the *hardware*
			- If there were *no* operating system, each program would have to interact with the hardware *directly*, 
				- This would be *inefficient* as each program would have to do everything *themselves*
				- This would likely *not work* in combination with other programs as each program tries to get *priority* from the *cores*
	- Roles
		- Referee
			- The OS *shares* the hardware *fairly* and *safely*
			- Each program gets *a turn* of a *few milliseconds* each so that every program can run *simultaneously*
			- Each program gets its own *designated part* in the RAM and storage so no program *infringes* upon or *changes* the data of another
			- Programs *can't* access the storage or RAM of *another* program
			- A program that *crashes* stays *contained* and does not result in the *whole* computer crashing
		- Translator
			- The OS handles hardware *drivers* so that programs can run on *any* hardware
			- Programs only *ask* the *OS* to perform a certain *action* (not the hardware directly)
			- Drivers are small programs that serve as the layer between *hardware* and the *OS*
				- *Translates* data sent *to* the hardware into *actions* for the hardware to take
				- *Translates* data *sent* from the hardware into *data* the OS can *use*
			- This results in ex. Spotify being able to run *no matter what* sound card the computer uses
	- OS families
		- UNIX
			- Made in 1969 by Bell Labs
			- Linux Kernel made in 1991
				- Linux, Ubuntu, Android
				- Servers, clouds and supercomputers mainly run Linux
				- Linux is uncommon for desktops and laptops
				- Most used OS worldwide
			- NeXTSTEP
				- iOS, Mac
				- Second most popular for desktops and laptops
			- PS5
		- MS-DOS
			- Windows
				- Most desktops and laptops
	- Functioning
		- Process Management
			- *Shares* the CPU between *all* running programs
			- Every running program is a *process* with its own *process ID* (**PID**)
			- OS gives each process *a turn* of a few *milliseconds* of *CPU time* each, then switches to the *next* in order
			- The window you're using gets *higher* priority
		- Memory Management
			- Gives each process its *own section* of RAM to *use*
			- When a program *starts*, it receives a *certain amount* of RAM storage to i, which is *taken back* when it *closes*
			- OS *prevents* processes from writing in *each other's* memory
			- When RAM is full, the OS moves unused data to the SSD (pagefile/ virtual memory)
		- File Management
			- *Organises* the storage into *files* and *folders*
			- OS tracks *location* of each file in storage
			- Uses a file system: 
				- NTFS on windows
				- APFS on macOS
				- ext4 on Linux
			- Checks for *permission* for file *editing* and *reading*
			- Programs themselves *never* know *where* in the memory a file is stored
		- Device Management
			- Lets programs *use* hardware through *drivers* that are *maintained* by the OS
			- Every device needs a *driver* to serve as the *translator* between hardware and program
			- The OS spots *new devices* and *loads* the correct driver for them
		- User Interface
			- How the user gives the OS instructions
			- GUI (graphical user interface)
				- Commands are sent through the computer *indirectly* through accessible interfaces
				- Windows, icons, mouse, buttons
				- Standard and easy to learn
			- CLI (command line interface)
				- Commands are typed *directly* to the computer
				- Much faster and easier to automate
		- Example
			- The icon of a word processor is pressed
			- 1) Device management
				- The mouse's click is translated into data for the OS and is interpreted as the word processor having to be opened
			- 2) File management
				- The program is located in storage and is loaded
			- 3) Process management
				- A new process is created that has a turn in the CPU time
			- 4) Memory management
				- The process is given a protected piece of RAM and is loaded into RAM
			- 5) User interface
				- A window containing the application is opened
