- Negative Numbers in Binary
	- Sign Bit Method
		- Number is split into *sign* and *magnitude*
			- Sign
				- Digit at the front that tells whether the number is positive or negative
				- **0** for *positive* and **1** for *negative*
			- Magnitude
				- All the numbers after the first, that contain the *value* of the number
			- Example
				- 1101
				- 1 - 101
				- -5
			- Problems
				- Two zeros
					- 0000 represents the value of 0 while 1000 represents the value of -0
					- This means there are two patterns for the same value
				- Addition breaks
					- Adding a number with the negative version of that number will often *not* result in **0**.
						- Adding 0101 (**5**) and 1101 (**-5**) results in (1)0010 (**2**) instead of 0000 (**0**)
					- *Addition* does not work with this method
	- Two's Complement Method
		- Conversion method
			- Take *positive* number in binary
			- *Flip* every bit: 0 -> 1 ->
			- Add **1** to the result
			- This method is used the exact same for positive to negative *and* vice versa
		- Negative binary to decimal
			- Convert first digit to a decimal and make it a negative
			- Convert all other digits to one decimal number
			- Add the two decimal numbers obtained together
		- Adding a number with the negative version of that number will *always* result in **0**
			- One bit will fall outside the *bit limit*, causing an overflow, making the result **0**
			- Adding 0101 (**5**) and 1011 (**-5**) together results in (1)0000 = **0**
		- The range is *not symmetrical*
			- Asymmetry in various formats
				- 4 bits
					- Smallest: -8
					- Largest: +7
				- 8 bits
					- Smallest: -128
					- Largest: 127
				- 16 bits
					- Smallest: -32 768
					- Largest: 32 767
			- Cause
				- The smallest number and its counterpart will always be the same
				- There are only a *limited* amount of patterns given the amount of bits. The values *including* and *between* the *smallest* value and the *largest* value (positive smallest -1) take up *all* of these values. There is *no room* for a *positive counterpart* of the *smallest* number.
				- Example
					- 1000 (**-8**)
					- 0111 (flip)
					- 1000 (add 1)
					- 4 bits = 16 patterns for values -8 -> 7
- Fractions in Binary
	- Decimal
		- 10^-1 = 0.1
		- 10^-2 = 0.01
		- 10^-3 = 0.001
	- Binary to decimal
		- Instead of *adding* to the *exponent* for every digit *before* the *comma* (x^2, x^3, x^4...), we instead *reduce* the *exponent* for every digit *after* the *comma* (2^-1, 2^-2, 2^-3)
		- Example: 0.101 binary to decimal
			- (1 x 0.5) + (0 x 0.25) + (1 x 0.125)
			- = 0.625
	- Decimal to binary
		- Instead of *dividing* by two like with whole decimal to binary conversions, we instead *multiply* by two
		- Process
			- 1) *Multiply* the number by *two*
			- 2) Write down **1** or **0**
				- If the outcome is *equal to or greater than* 0, write down a **1**
				- If the outcome is *lower than* 0, write down **0**
				- The first number is written in the leftmost slot and each following number is written to the right of it
			- 3) Take the *mantissa* (fractional part) of the outcome obtained in *step 1*.
			- 4) Repeat from step 1 using the mantissa obtained in step 3 until the mantissa = 0
		- Example (0.375 -> binary)
			- 0.375 x 2 = **0**.*75*
				- Write down **0**
			- 0.*75* x 2 = **1**.5
				- Write down **1**
			- 0.5 x 2 = 1.*0*
				- Write down 1
			- Mantissa = *0*
			- Write down obtained numbers in order = 0.011
	- Irrational numbers in binary
		- Certain numbers in binary may be *irrational* the same way certain numbers in decimal may be irrational (0.33.., 3.141..)
		- This is true for **0.1** in binary
			- 0.1 in binary = 0.0001100110011...
	- Storing decimal numbers in binary
		- Scientific notation
			- *Every* number is a *mantissa* times a *power* of the *base*
				- Examples
					- 170 -> 1.7 x 10^2
					- 1.7 -> 1.7 x 10^0
					- 0,000000017 -> 1.8  10^-8
		- Floating point
			- Formula
				- (**-1**)^*S* x **1**.*M* x **2**^*E*
				- S = Sign bit
					- 0 = positive
					- 1 = negative
				- E = Exponent
					- How far the point shifted, plus a fixed bias
				- M = Mantissa
					- The digits *after* the leading 1 (that 1 is never stored)
			- Floating point in 8-bit format
				- (0)"1010"{101}
					- () = S (1 bit)
					- "" = E (4 bits, bias 7)
					- {} = M (3 bits)
				- More than 8 bits
					- Real computers almost never use 8 bits for fractional notation
					- Different formats

							- 8 bits
							- S = 1
							- E = 4
							- M = 3
							- Bias = 7

							- S = 1
							- E = 8
							- M = 23
							- Bias = 127
						- IEEE 754 double

							- S = 1
