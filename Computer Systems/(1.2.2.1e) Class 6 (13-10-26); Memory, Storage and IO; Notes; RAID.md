- RAID
	- Problem to fix
		- Hard disks can wear out and break, about 1-2% a year
		- Data centres can have hundreds of thousands of disks
	- RAID
		- Redundant Array of Independent Disks
		- *Several* discs that the OS sees as *one* drive
		- Goal 1 (speed/ striping)
			- Spread the work over several disks at once
			- This can make the files *faster* to retrieve because the workload is spread out
		- Goal 2 (keep running/ redundancy)
			- Store data so that a dead disk loses nothing
			- Always results in extra capacity
	- RAID 0: striping
		- Alternating *chunks* between *two* disks
		- Example
			- A1 goes to disk 1
			- A2 goes to disk 2
			- A3 goes to disk 1
			- A4 goes to disk 2
		- Cost: 
			- *2* disk operations per small write
			- *None* of the storage is *redundant*
	- RAID 1: mirroring
		- Complete *copy* of all data on *another* disc
		- If one disc dies, the data will be *preserved* on the other disc
		- Example
			- A1 goes to disk 1 and 2
			- A2 goes to disk 1 and 2
			- A3 goes to disk 1 and 2
			- A4 goes to disk 1 and 2
		- Cost: 
			- *2* disk operations per small write
			- *Half* of the storage is *redundant*
	- RAID 5: striping with rotating parity
		- Introduces *parity* that can *reconstruct* corrupted data
		- Workings 
			- Every section of n-1 (where n is number of disks, in the case of 4 disks so 3) bits is ended with a *parity bit*.
			- Every new section the *parity bit* swaps places with the bit to the right or back to first place if at the end of the section.
			- Three disks
				- Parity is determined using an XOR operator
				- If two bits are the same, parity is 0
				- If two bits are different, parity is 1
			- Four+ disks
				- Parity is determined by counting up all 1s across a row of discs
				- If that number is even, parity is 0
				- If that number is odd, parity is 1
		- Should *one* disk be destroyed, the disk can be *remade* by using the *parity* from other disks
		- Cost:
			- *4* disk operations per small write
			- *1* disk worth of storage is given up for parity
		- Used mostly for *file servers*
		- When a *disk* is lost and then *additional* data is lost *during* reconstruction, reconstruction of data becomes *impossible*
	- RAID 6: two parity blocks
		- Similar to RAID 5, but every section is ended with two *identical* parity bits
		- RAID 6 can survive a *second* failure during *reconstruction*, unlike RAID5
		- Used for big arrays (6+ disks) of large hard disks, backup servers and archives
	- RAID 10: mirror pairs, striped
		- Several mirror pairs are made, each being composed of an identical number of several disks.
		- Usually each mirror pair is composed of two disks
		- Data is written alternatingly on these mirror pairs. Disks within mirror pairs have copies of the same data written to them
		- Cost
			- *Half* of the storage is *redundant*
			- If *all* disks from the *same* mirror pair are lost, then *all data* becomes lost
- Shortcomings of RAID
	- RAID protects against disks dying
	- RAID does not against deleting, ransomware or file theft
