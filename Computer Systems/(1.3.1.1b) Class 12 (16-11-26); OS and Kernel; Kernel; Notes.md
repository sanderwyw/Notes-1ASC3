- Kernel
	- Purpose
		- The kernel is *part of the OS* that talks to the hardware directly
			- It has *full* control over *all* hardware
				- It is also the *only* part with this attribute
			- The *OS* and *all applications* can *only* access the hardware *through the kernel*, not directly
		- Ex. The shell 
			- The shell is a program on top of the kernel; it reads your commands and transfers them to the kernel to be carried out
	- Types
		- Monolithic Kernel
			- The whole kernel exists as *one cohesive unit*
			- Programs, memory, files, drivers and network are *all* run by the *same* kernel
			- Very *efficient*
			- If *one* part of the kernel crashes the *whole* system crashes
			- Used by Linux and Windows
			- Example
				- *All* cooks share the *same* kitchen and thus work very *fast*, but *one* fire in the kitchen results in the *whole* kitchen being *shut down*
		- Microkernel
			- The kernel only runs at a basic level
				- Running programs
				- Passing messages
				- Interpreting devices
			- Files, drivers and network run as *separate* programs *outside* the kernel
			- Slow
			- *One* crash *doesn't* result in a *systemwide* crash
			- Used by car systems (QNX)), MINIX
		- Most OS will use a *mix* of monolithic kernel (for the OS itself) and microkernels (drivers)
	- Kernel-level risks
		- Risks
			- Programs that run on the (monolithic) kernel are much *more difficult to track* and can easily *crash the whole system*
			- There are *no safety nets* in place for kernel-level crashes, resulting in an instant *blue screen* with *little hope* for *data recovery*
		- Kernel-level anti-cheat
