IPv6 GUA Assignment
	- IPv6 GUA Assignment
		- GUA *(Global Unicast Address)*
		- A *IPv6* enabled *router* periodically sends *ICMPv6 RAs* which simplifies **how** a host *can* dynamically **create** or **acquire** its *IPv6* configuration
		- Dynamic GUA Assignment
			- Stateless (**No device** is tracking the assignment of IPv6 addresses)
				- SLAAC only
					- *Router* **sends** *RA messages* which provides **IPv6 addressing information**
					- *Hosts* **use** *RA information* for all their addressing including **creating their own GUA**
				- SLAAC with DHCP server
					- *Router RA messages* provide IPv6 configuration information to hosts and inform them to **contact a stateless DHCPv6 server** for **additional configuration information**
					- *Hosts* **use** *RA information* to create their one unique *GUA* and get **additional information** from a *DHCPv6 server*
			- Stateful (**A DHCPv6 server** is managing the assignment of IPv6 addresses )
				- DHCPv6 Server
					- *Router RA messages* **inform** hosts to **contact** a *stateful DHCPv6 server* or *router* for all IPv6 **information**
					- *Hosts* **contact** a *DHCPv6* server to acquire all of their *IPv6* addressing **information**
	- Three RA Message Flags
		- **How** a client obtains an *IPv6 GUA* **depends on settings** in the *RA message*
		- An *ICMPr6 RA message* includes **three flags**
			- A flag
				- Address Autoconfiguration flag
				- Signifies to **use** *SLAAC* to create *IPv6 GUA*
			- O flag
				- Other Configuration flag
				- Signifies that **additional information** is **available** from a stateless *DHCPv6 server*
			- M flag
				- Managed Address Configuration flag
				- Signifies to **use** a *stateful DHCPv6 server* to obtain a *IPv6 GUA*
	- Duplicate Address Detection
		- A *SLAAC host* may use the following *duplicate address detection* **process** to ensure that the *IPv6 GUA* is **unique**
			- Host sends *ICMPv6 Neighbor Solicitation (NS)* message with a specially constructed solicited-node multicast address containing the **last 24 bits** of *IPv6 address* of the *host*
			- If **no other** devices respond with a *Neighbor Advertisement (NA)* message, then the address is virtually guaranteed to be **unique**
- DHCPv6
	- DHCPv6 Operation Steps
		- Stateful DHCP does **not** require *SLAAC* while *stateless DHCPv6* does
		- When a RA indicates to use DHCPv6 or stateful DHCPv6
			- 1. *Host* sends *RS message*
			- 2. *Router* responds with *RA message*
			- 3. *Host* sends *DHCPv6 SOLICIT* message
			- 4. *DHCPv6* server responds with an *ADVERTISE* message
			- 5. *Host* responds to the *DHCPv6 server*
			- 6. *DHCPv6* server sends a *REPLY* message
	- Enabling Stateless DHCPcv6 on an Interface
		- *Stateless DHCPv6* is enabled using the **ipv6 nd other-config-flag** in *R1(config-if)#*
			- This sets the *O flag* to 1
		- *Stateful DHCPv6* is enabled using the **ipv6 nd managed-config-flag** in *R1(config-if)#*
			- This sets the *M flag* to 1
- Configure DHCPv6 Server
	- Stateless DHCPv6 server option requires that the router advertises the *IPv6 network* addressing information in *RA messages*
