- IPv6
	- 128-bit
	- Hexadecimal
	- Written as x:x:x:x:x:x:x:x with each x consisting of four hexadecimal values which are made up of 4 bits each
	- Prefix
		- Represented in slash notation to indicate the network portion of an IPv6 address
			- Ranges from 0 to 128
			- Recommended is /64
- IPv6 GUA (Global Unicast Address)
	- Similar to **public** IPv4 address
	- Globally unique
	- Internet routable
	- Structure
		- Global routing Prefix
			- Prefix or **network** portion of the address that is assigned by the provider
			- Varies based on *ISP* (Internet Service Provides) policies
		- Subnet ID
			- Area between the **Global Routing Prefix** and the Interface ID
			- Used by an organization to identify **subnets** within its site
			- Equivalent to **network** portion of an IPv4 address
		- Interface ID
			- Equivalent to **host** portion of an IPv4 address
			- /64 subnets should be used
- IPv6 LLA (Link-local Address)
	- Within fe80::/10 range
	- Required for IPv6-enabled devices to communicate with other devices on same local link/ subnet
	- Not routable and confined to a single link (subnet)
	- Will be created by device if not manually configured on interface
- IPv6 ULA (Unique Local Address_
	- Within fc00::/7 to fdff::/7
	- Similar to IPv4 private addresses
	- Unique local addresses are used for **local** addressing within a site or between a **limited number of sites**
	- Can be used for devices that will never need to access another network
- IPv6 Dynamic Addressing
	- RS messages (router solicitation)
		- Sent by **host devices** to discover IPv6 routers
	- RA messages (router advertisement)
		- Sent by **routers** to make hosts configure their IPv6 GUA address as detailed by info sent within the RA
			- Three methods are provided
				- SLAAC
				- SLAAC with stateless DHCPv6 server
				- Stateful DHCPv6 (no SLAAC)
		- Provides useful information
			- Network prefix and length
			- Default gateway address
			- DNS address and domain name

- CSMA/CD
	- Carrier-sense multiple access
	- Used by legacy Ethernet LANs
	- MAC protocol (medium access control)
	- Operates in **half-duplex** mode where only **one device** sends or receives **at a time**
	- Protocol in which a node **verifies** the **absence of other traffic** before transmitting on a shared transmission medium
	- Collision detection process
		- Devices transmitting **simultaneously** will result in a **signal collision** on the shared media
		- Devices **detect** the **collision**
		- Devices wait a **random** period of time and **retransmit** data
- CSMA/CA
	- Used by IEEE 802.11 WLANs
		- Operates in half-duplex mode where only one device sends or receives at a time			- Uses a **collision avoidance process** to **govern** when a device can **send** and **what happens** if **multiple devices send** at the **same time**
		- Collision avoidance process
			- When **transmitting**, devices also **include** the **time duration needed** for the transmission
			- Other devices on the shared medium **receive** the **time duration** information and **know how long** the medium will be **unavailable**
- MAC
	- One of two primary addresses assigned to a device on a LAN
	- **Physical** address (compared to **logical** IP address)

- ARP (Address Resolution Protocol)
	- Overview
		- Destination IPv4 address => destination MAC address
		- Maintains an **ARP table** which keeps track of **IPv4** to **MAC** mappings
	- Functionality
		- To send a frame, a device will look through its **ARP table** for a given **destination IPv4 address** and its corresponding **MAC address**
			- Given destination IPv4 address is on the **same network**
				- Device searches ARP table for given destination IPv4 address
				- If given destination IPv4 address is found, its destination MAC address is used
			- Given destination IPv4 address is on a **different** network
				- Device searches ARP table for IPv4 address of default gateway
				- If default gateway is found, its destination MAC address is used
			- If no entry is found in the MAC table, the device sends an ARP request
		- Removing entries from the MAC table
			- Entries are removed when the **ARP cache timer** expires or when manually removed by admin
	- Issues
		- ARP requests are received and processed by **every** device on the local network (reduction in performance)
- TCP (Transmission Control Protocol)
	- Overview
		- Provides reliability and flow control of data packets
		- TCP is a stateful protocol, which means it keeps track of the state of the communication session
		- L4 protocol
	- Operations
		- Establishes a session
			- TCP is **connection-oriented** and establishes a permanent connection/ session **before** forwarding any traffic
		- **Numbers** and **tracks** **data segments** transmitted to a host from an application
		- Acknowledges received data
		- Retransmits data that is lost along the way
		- Sequence data that might arrive in wrong order back to the right order
		- Sends data at an efficient rate that is acceptable by the receiver
			- Will request that the sending application reduces the rate of data flow if its own resources are overtaxed
		- Used when it is important that **all** the data arrives in its **proper sequence**
	- Header
		- Source port
			- 16-bit field
		- Destination port
			- 16-bit field
		- Sequence number
			- 32-bit field used for data reassembly
		- Acknowledgment number
			- 32-bit field used to indicate that data has been **received** and that the **next byte** is **expected** from source
		- Header Length
			- A 4-bit field known as "data offset" that indicates the length of the TCP segment header
		- Reserved
			- A 6-bit field that is reserved for **future use** *?*
		- Control bits
			- A 6-bit field that includes *flags* which indicate the **purpose** and **function** of the *TCP segment*
		- Window size
			- A 16-bit field used to indicate the **number of bytes** that can be accepted at a time
		- Checksum
			- A 16-bit field used for **error checking** of the segment header and data
		- Urgent
			- A 16-bit field used to indicate if the contained data is **urgent**
- UDP ()
	- Overview
		- Reconstructs data in the order that it is received
		- Does not resend **lost** segments
		- Does not establish **session**
		- Does not inform sender about **resource availability**
		- Use cases
			- Live video and multimedia applications
			- Simple request and reply applications
			- Applications that handle reliability themselves
