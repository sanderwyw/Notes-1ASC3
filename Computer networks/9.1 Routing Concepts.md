- Path Determination
	- Functions of Router
		- When a *router* receives an *IP packet*, it **determines** which interface to use to **forward** the *packet* to the *destination*. This is known as **routing**
			- The *destination* may be an *end device* or a *network* connected to another *router*
		- **Determine best path** to forward packets based on information in *routing table*
		- **Forward packets** towards *destination*
	- Best Path Equals Longest Match
		- The **best path** in the routing table is also known as the **longest match**
		- The *routing table* contains route entries consisting of 
			- A prefix (network address)
			- Prefix length
		- Looks for **match** between *destination IP address* of packet and *route in routing table*
		- *Longest match* is the route in the *routing table* that has the **greatest number** of **far-left** matching bits with the **destination IP address** of the packet.
			- Longest match is always the preferred route
		- The *IPv4* address with a longer subnet mask will be a better match than a shorter one
			- destination = 172.16.0.10
			- 172.16.0.0/26 is **better** than 172.16.0.0/12
		- This also applies for *IPv6* but if the *subnet mask* is **longer** than the *destination subnet mask* it becomes **invalid**
			- destination = 2001:db8:c000::99/48
			- 2001:db8:c000::*/40* is **worse** than 2001:db8:c000::*/48*
			- 2001:db8:c000:5555::*/64* is **invalid**
	- Building the Routing Table
		- Directly Connected Networks
			- Added to the *routing table* when a *local interface*:
				- Is configured
					- with *IP address* 
					- with *subnet mask*
				- Is active
		- Remote Networks
			- Networks that are **not directly connected** to the router
			- Routers learn about *remote networks* in two ways
				- Static routes
					- Added to *routing table* when a route is manually configured
				- Dynamic routing protocols
					- Added to *routing table* when routing protocols **dynamically learn** about the *remote network*
		- Default Route
			- Specifies a **next-hop** *router* to use when the routing table **does not contain** a specific route that matches the destination IP address
			- Can be entered manually as a *static route* or learned automatically from a *dynamic routing protocol*
			- Has a /0 prefix length
				- No bits need to match the destination IP address
- Packet forwarding
	- Packet Forwarding Decision Process
		- **1.** The *data link frame* with an *encapsulated IP packet address* arrives on the ingress interface
		- **2.** The *router* examines the *destination IP address* in the *packet header* and consults its IP routing table 
		- **3.** The *router* finds the *longest matching prefix* in the *routing table*
		- **4.** The *router* **encapsulates** the packet in a *data link frame* and forwards it out the egress interface
		- **5.** If there is **no** *matching route entry* the packet is **dropped**
	- After a router has determined the best past it could do the following
		- Forward the Packet to a Device on a Directly Connected Network
			- If the *route entry* indicates that the egress interface is a *directly connected network*, the packet can be forwarded **directly** to the *destination device*
				- Typically an ethernet LAN
			- To **encapsulate** the packet in the *ethernet frame*, the *router* needs to determine the *destination MAC address* associated with the *destination IP address* of the packet
				- Process varies based on whether the packet is *IPv4* or *IPv6*
		- Forward the Packet to a Next-Hop Router
			- If the route entry indicates that the IP address is on a *remote network*, the packet must be forwarded to the *next-hop router*
				- This *router address* is indicated in the *route entry*
			- If the forwarding router and the next-hop router are on an *ethernet network*, *ARP* and *ICMPv6 Neighbor Discovery* will determine the *destination MAC address* of the packet as previously described. 
				- Difference is that the *router* will **search** for the *IP address* of the *next-hop router* in its *ARP table* or *neighbor cache* instead of the *destination IP address* of the **packet**
		- Drop the Packet - No Match in Routing Table
			- If there is **no match** between the *destination IP address* and a *prefix* in the *routing table* and there is **no** *default route*, the **packet** will be **dropped**

- IP Routing Table
	- Routing Sources
		- Contains a **list of routes to known networks** (prefixes and prefix lengths)
		- Source of information is derived from following
			- Directly connected networks
			- Static routes
			- Dynamic routing protocols
		- The *source* for each route in the routing table is identified by a **code**
		- Common codes include the following
			- L - Identifies the **address** assigned to a *router interface*
			- C - Identifies a *directly connected network*
			- S - Identifies a *static route* created to reach a *specific network*
			- O - Identifies a *dynamically learned network* from another router using the *OSPF* routing protocol
			- * - This route is a **candidate** for a default route
	- Routing Table Principles
		- There are **three** routing table principles as described in the table
			- Every router makes it decision **alone**, based on the information it has in its **own** *routing table*
			- The information in a *routing table* of one router **does not necessarily match** the *routing table* of **another** *router*
			- **Routing information** about a *path* does not provide *return routing information*
	- Routing Table Entries
		- Route source
			- Identifies **how** the route was learned
			- O, S, C, L, *
		- Destination network (prefix and prefix length)
			- Identifies address of remote network
		- Administrative distance
			- Identifies **trustworthiness** of the route source
		- Metric
			- Identifies the *value* assigned to reach the remote network
			- Lower values indicate preferred routes
		- Next-hop
			- Identifies the IP address of the *next router* to which the packet would be forwarded
		- Route timestamp
			- Identifies how much time has passed since *route* was **learned**
		- Exit interface
			- Identifies the egress interface to use for outgoing packets to reach their final destination
	- Directly Connected Networks
		- To learn about any remote networks, the *router* must have **at least one** active interface configured with an *IP address* and subnet mask (prefix length)
			- This is known as a *directly connected network* or *directly connected route*
			- Routers add a *directly connected route* to its *routing table* when an interface is configured with an IP address and is activated
		- A *directly connected network* is denoted by a *status code of C* in the routing table
			- The route contains a *network prefix* and *prefix length*
			- Routing table also contains a local route for each of its directly connected networks, indicated by the *status code of L*
		- For *IPv4* local routes the prefix length is **/32** and for *IPv6* the prefix length is **/128**
			- This means the *destination IP address* of the packet must match **all of the bits** in the *local route* for this route to be a match
	- Static Routes
		- Provides ease of routing table maintenance in **smaller** networks that are **not expected to grow** significantly 
		- Uses a **single default route** to represent a path to any network that does not have a more specific match with another route in the routing table
		- Routes to and from *stub networks*
			- A *stub network* is a network accessed by a single route and the route has only **one neighbor**
