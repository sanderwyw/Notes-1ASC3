- Mitigating DHCP Attacks
	- DHCP Attack Review
		- DHCP Starvation attack
			- Creates DoS for connecting clients
			- Uses attack tools such as Gobbler
			- Can be mitigated by using port security
			- Gobbler could be configured to use the actual interface MAC as source Ethernet address, but specified to use a different Ethernet Address in the DHCP payload. This 
		- DHCP Spoofing attack
			- Impersonating a server
			- Also uses attack tools such as Gobbler
			- More difficult to mitigate
	- DHCP Snooping
		- Filters DHCP messages and rate-limits DHCP traffic on untrusted ports
			- Devices under administrative control (switches, routers and servers) are trusted
			- Trusted interfaces (trunk links, server ports) must be explicitly configured as trusted
			- Devices outside the network and all access ports are generally treated as untrusted sources
		- Builds a DHCP table that includes the source MAC address of a device on an untrusted port and its IP address as assigned by the DHCP server
			- MAC and IP addresses are bound together
			- Also called DHCP snooping binding table
	- Steps to Implement DHCP Snooping
		- Enable DHCP snooping by using the *ip dhcp snooping* global configuration command
		- On trusted ports, use the *ip dhcp snooping trust* interface configuration command
		- On untrusted interfaces, limit the number of DHCP discovery messages that can be received using the *ip dhcp snooping limit (packet-per-second)* interface configuration command
		- Enable DHCP snooping by VLAN or by a range of VLANs, by using the *ip dhcp snooping (vlan)* global configuration command
	- Extra
		- Use the *show ip dhcp snooping* privileged EXEC command to verify DHCP snooping settings
		- Use the *show ip dhcp snooping binding* command to view the clients that have received DHCP information
