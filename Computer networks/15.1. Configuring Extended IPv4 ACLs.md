- Configuring Extended IPv4 ACLs
	- Extended ACLs
		- Extended ACLs provide a greater degree of control
		- Can filter on 
			- Source address
			- Destination address
			- Protocol
				- IP
					- Any Internet Protocol
				- UDP
					- User Datagram Protocol
				- TCP
					- Transmission Control Protocol
						- Domain
						- FTP
						- FTP-data
						- Pop3
						- Smtp
						- Telnet
						- Www
				- ICMP
					- Internet Control Message Protocol
			- Port number
		- Can be created as
			- Numbered Extended ACL
				- Created using *access-list (access-list-number)* global config command
			- Named Extended ACL
				- Created using *ip access-list extended (access-list-name)*
		- Examples
			- *access-list 100 permit tcp any any eq www*
				- This configures an extended ACL 100 to filter HTTP traffic
				- Uses the *www* port name
			- *access-list 100 permit tcp any any eq 80*
				- Also configures an extended ACL 100 to filter HTTP traffic
				- Uses port number *80*
				- Both ACE achieve the same result
			- *access-list 100 permit tcp any any eq 22*
			- *access-list 100 permit tcp any any eq 443*
				- If there is no specific protocol name listed, configuring the port number is required
					- SSH = port number 22
					- HTTPS = port number 443

	- Applying a Numbered Extended IPv4 ACL
		- Examples
			- *access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq www*
			- *access-list 110 permit tcp 192.168.10.0 0.0.0.225 any eq 443*
			- *interface g0/0/0*
			- *ip access-group 110 in*
				- ACL permits both HTTP and HTTPS traffic from the 192.168.10.0 network to go to any destination
				- ACL 110 is applied inbound on the R1 G0/0/0 interface
				- Extended ACLs can be applied in various locations but are most commonly applied close to the source
	- TCP Established Extended ACL
		- IOS can also perform basic stateful firewall services using the TCP *established* keyword
			- Enables **inside traffic** to **exit** the **IPN** (inside private network), and permits the returning **reply traffic** to **enter** the **IPN**
			- TCP traffic generated by an **outside host** and attempting to communicate with an **inside host** is **denied**
			- Essentially all traffic that comes from hosts that the IPN hasn't communicated with themselves is denied
			- A match occurs if the returning TCP segment has the ACK or RST (reset) flag bits set, indicating that the packet belongs to an existing connection
		- Use *show access-lists* command to show that hosts are accessing the secure web resources from the internet
		- Examples
			- *access-list 120 permit tcp any 192.168.10.0 0.0.0.255 established*
			- *interface 0/0/0*
			- *ip access-group 120 out*
			- *end*
				- ACL 120 is configured to only permit returning web traffic to the inside hosts
				- ACL is then applied outbound on the R1 g0/0/0 interface
	- Named Extended IPv4 ACL Syntax
		- Naming an ACL makes it easier to understand its function
		- Use the *ip access-list extended (access-list-name)* config command to create a named extended ACL
		- Examples
			- *R1(config)# ip access-list extended NO-FTP-ACCESS
			- *R1(config-ext-nacl)#
		- Scenario
			- SURFING
				- Permits HTTP and HTTPS traffic to exit to the internet
			- BROWSING
				- Only permits returning web traffic to the inside hosts while all other traffic exiting the R1 g0/0/0 interface is denied
			- Syntax
				- *ip access-list extended SURFING*
				- *Remark Permits inside HTTP and HTTPS traffic*
				- *permit tcp 192.168.10.0 0.0.0.255 any eq 80*
				- *permit tcp 192.168.10.0 0.0.0.255 any eq 443*
				- *exit*
				- *ip access-list extended BROWSING*
				- *Remark Only permit returning HTTP and HTTPS traffic
				- *permit tcp any 192.168.10.0 0.0.0.255 established*
				- *exit*
				- *interface g0/0/0*
				- *ip access-group SURFING in*
				- *ip access-group BROWSING out*
				- *end*
				- Use *show access-lists* to verify the ACL statistics
	- Editing Extended ACLs
		- An extended ACL can be edited using a text editor when many changes are required
		- If the edit applies to one or two ACEs, sequence numbers can also be used
		- Example
			- The ACE sequence number 10 in the SURFING ACL has an incorrect source IP network address
			- Remove the statement with *no (sequence)* command
			- Re-add the statement with the *(sequence) permit tcp 192.168.10.0 0.0.0.255 any eq www* command
			- Syntax
				- *ip access-list extended SURFING*
				- *no 10*
				- *10 permit tcp 192.168.10.0 0.0.0.255 any eq www*
				- *end*
				- *show access-lists*
