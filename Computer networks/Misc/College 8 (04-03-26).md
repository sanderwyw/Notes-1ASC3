When a host uses **autoconfiguration**, it typically sets **four** key parameters:

- **APIPA (IPv4)** → only IP + mask. No gateway, no DNS.

 DHCPv4: Obtaining a New Lease (DORA)

The four messages are:

1. **DHCPDISCOVER** — client broadcasts to find DHCP servers.
2. **DHCPOFFER** — server proposes an address + config.
3. **DHCPREQUEST** — client requests the chosen offer.
4. **DHCPACK** — server confirms the lease.

### Highest OSI layer used by DHCP

- **Application layer (Layer 7)**

DHCP runs over UDP (ports 67/68), but the protocol itself is considered L7.

### Destination IP addresses used

- **Broadcast 255.255.255.255** for DISCOVER and REQUEST (initial).
- **Server’s unicast IP** for OFFER and ACK (server → client).
- **Client may still use broadcast** for REQUEST if it has no IP yet.

##   DHCPv4 Lease Renewal

### How to check the DHCP lease time on your Wi‑Fi interface (Windows)

Use:

`ipconfig /all`

Look for your Wi‑Fi adapter and note:

- **Lease Obtained**
- **Lease Expires**

This gives you the renewal timeline (T1, T2).

Only the Request and Pack is needed for a renewed lease

### What is a DHCP relay?

A **DHCP relay** is a router or switch that **forwards DHCP messages between clients and a DHCP server on a different subnet**.

### When do you need it?

- When **clients and the DHCP server are not on the same Layer‑2 network**.
- Because DHCP uses **broadcasts**, and broadcasts do **not cross routers**.
- The relay converts the broadcast into a **unicast** to the DHCP server.
