- Endpoint Security
	- Network attacks today
		- Distributed Denial of Service (DDoS)
			- Coordinates attack from many devices with the intention of degrading or halting public access to an organization's website and resources
		- Data Breach
			- Attack in which an organization's data servers or hosts are compromised to steal confidential information
		- Malware
			- An attack in which an organization's hosts are infected with malicious software that cause a variety of problems. 
				- For example, WannaCry encrypts the data on a host and locks access to it until a ransom is paid
	- Network Security Devices
		- Virtual Private Network (VPN)
			- Provides a secure connection to remote users across a public network and into the enterprise network. VPN services can be integrated into the firewall
		- Next-Generation Firewall (NGFW)
			- Provides stateful packet inspection
			- Application visibility and control
			- Next-generation intrusion prevention system (NGIPS)
			- Advanced malware protection (AMP)
			- URL filtering
		- Network Access Control (NAC)
			- Includes AAA services
			- In larger enterprises these services might be incorporated into an appliance that can manage access policies across a wide variety of users and device types
		- Endpoint Protection
			- Endpoints are hosts like laptops, desktops, servers and IP phones.
				- They are vulnerable to malware-related attacks that originate through email or web browsing
			- Endpoints usually use host-based security features such as 
				- Antivirus/ antimalware
				- Firewalls
				- Host-based intrusion prevention systems (HIPs)
			- Endpoints today are protected by a combination of 
				- NAC
				- AMP software
				- Email security appliance (ESA)
				- Web security appliance (WSA)
- Access Control
	- Authentication with a local password
		- Simplest method of remote access authentication
		- Can be configured on console, VTY lines and aux ports
		- SSH (Secure Shell)
			- Allows for the operation of network services securely over a unsecured network
			- Requires login via username and password
				- Can only be authenticated locally
		- Local database method has its limitations:
			- User accounts must be configured locally on each device (not scalable)
			- Provides no fallback authentication method
				- If you forget your password your cooked
	- AAA Components
		- Stands for
			- Authentication
				- Specifies who is permitted to access a network
				- Local AAA Authentication
					- Method stores usernames and passwords locally in a network device (e.g. router)
					- Users authenticate against the local database
					- Ideal for small networks
				- Server-Based AAA Authentication
					- Router accesses a central AAA server
					- Passwords and usernames are stored on a server
					- AAA server contains the usernames and passwords for all users
					- Router uses either the Remote Authentication Dial-In User Server (RADIUS) or Terminal Access Controller Access Control System (TACACS+) protocols to communicate with the AAA server
					- Ideal when there are multiple routers and switches
			- Authorization
				- Specifies what individuals can do while they are connected to a network
				- Automatic and does not require users to perform additional steps after authentication
				- Governs what users can and cannot do on the network after they are authenticated
				- Authorization uses a set of attributes that describes the user's access to the network
					- They are used by the AAA server to determine privileges and restrictions for that user
			- Accounting
				- Records and reports what actions were performed by those accessing a network
				- Can be used for auditing or billing
				- Collected data might include start and stop connection times, executed commands, number of commands and number of bytes
			- 802.1X
				- The IEEE 802.1X standard is a port-based access control and authentication protocol
				- This protocol restricts unauthorized workstations from connection to a LAN through publicly accessible switch ports
				- The authentication server authenticates each workstation that is connected to a switch port before making available any services offered by the switch or the LAN
				- The devices in the network with 802.1X have specific roles:
					- Client (Supplicant)
						- Device running 802.1X-compliant software
					- Switch (Authenticator)
						- The switch acts as an intermediary between the client and the authentication server
						- It requests identifying information from the client, verifies that information with the authentication server and relays a response to the client
					- Authentication server
						- The server validates the identity of the client and notifies the switch that the client is or is not authorized to access the LAN and switch services

		- Port Security
			- Prevents many types of attacks 
			- Including MAC address flooding
			- Including DHCP starvation
		- DHCP Snooping
			- Prevents DHCP starvation
			- Prevents DHCP spoofing
		- Dynamic ARP Inspection (DAI)
			- Prevents ARP spoofing
			- Prevents ARP poisoning
		- IP Source Guard (IPSG) 
			- Prevents MAC and IP address spoofing attacks

			- Use a dedicated management VLAN where nothing but management traffic resides

- MAC Address Table Attack
	- Recap
		- A L2 LAN switch builds a MAC table based on the source MAC addresses in received frames.
	- MAC Address Table Flooding
		- All MAC tables have a maximum size and can thus run out of resources
		- MAC Address Table Flooding attacks bombard the switch with fake source MAC addresses until the table is full and thus unusable
		- The switch will treat frames as an unknown unicast and begins to flood all incoming traffic out all ports on the same VLAN
			- This allows a threat actor to capture all frames sent form one host to another on the local LAN or VLAN
			- Traffic is only flooded within the local LAN or VLAN
		- Macof
			- Common MAC Address Table Flooding tool
			- Can create an attack very quickly
				- 8000 bs frames per second, most switches can store around 130000 MAC addresses
		- When the MAC address table is full it starts flooding out all ports including those connected to other switches, potentially causing the damage to spread
	- MAC Address Table Attack Mitigation
		- Port security is needed
		- Will only allow a specified number of source MAC addresses to be learned on the port
- LAN Attacks
	- DHCP servers dynamically provide 
		- IP configuration information
		- IP address
		- Subnet mask
		- Default gateway
		- DNS servers
	- Types of DHCP attacks
		- DHCP Starvation
			- Creates a DoS for connecting clients
			- Requires a tool such as Gobbler
				- Gobbler looks at the entire range of leasable IP addresses and tries to lease them all
				- It does this by creating DHCP discovery messages with bogus MAC addresses
		- DHCP Spoofing
			- Occurs when a rogue DHCP server is connected to the network and provides false IP configuration parameters to legitimate clients. 
			- A rogue server can provide a variety of misleading information, including the following
				- Wrong default gateway
					- Rogue server provides an invalid gateway or the IP address of its host to create a man-in-the-middle attack
					- Can easily go undetected as the intruder intercepts the data flow but doesn't necessarily alter it
				- Wrong DNS server
					- The rogue server provides an incorrect DNS server address pointing the user to a nefarious website
				- Wrong IP address
					- Rogue server provides an invalid IP address effectively creating a DoS attack on the DHCP client
	- ARP Attacks
		- Recap
			- Hosts broadcast ARP Requests to determine the MAC address of a host with a destination IP address
			- All hosts on the subnet receive and process the ARP request
				- The host with the matching IP address in the ARP Request sends an ARP reply
			- IP -> MAC address
		- A client can send an unsolicited ARP Reply called a "gratuitous ARP"
			- Other hosts on the subnet store the MAC address and IP address contained in the gratuitous ARP in their ARP tables
		- An attacker can send a gratuitous ARP message containing a spoofed MAC address to a switch, and the switch would update its MAC table accordingly.
			- In a typical attack, a threat actor sends unsolicited ARP Replies to other hosts on the subnet with the MAC Address of the threat actor and the IP address of the default gateway, effectively setting up a man-in-the-middle attack
		- Many tools for creating ARP man-in-the-middle attacks exist
		- IPv6 uses ICMPv6 Neighbor Discovery Protocol for L2 address resolution
		- IPv6 includes strategies to mitigate Neighbor Advertisement spoofing, similar to the way IPv6 prevents a spoofed ARP Reply
		- They are mitigated by implementing Dynamic ARP Inspection (DAI)
	- Address Spoofing Attacks
		- IP address spoofing is when a threat actor uses a random IP address or steals a valid IP address of another host to connect to a network when they are not authorized
		- MAC address spoofing is when a threat actor alters the MAC address of their host to match another known MAC address of a target host
			- The switch overwrites the current MAC table entry and assigns the MAC address to the new port
			- The switch then forwards all frames destined for the original host to the attacking host
		- When the original target host sends traffic, the switch will correct the error, changing the MAC address to the original port
			- To prevent this from happening, the threat actor can create a program that will constantly send frames to the switch so that the switch maintains the incorrect or spoofed information
		- Address Spoofing Attack mitigation
			- There is no security mechanism at L2 that allows a switch to verify the source of MAC addresses, which is what makes it so vulnerable to spoofing
			- IP and MAC address spoofing can be mitigated by implementing IP Source Guard (IPSG)
