	- Ethernet frame fields
		- **Minimum** ethernet frame size is **64 bytes** and the **maximum** is **1518 bytes**. Preamble field is **not included** when describing the size of the frame
		- A frame **less than 64 bytes** in length is considered a *collision fragment* or *runt frame* and is automatically **discarded**
		- A frame with **more than 1500 bytes** of data are considered *jumbo* or *baby giant frames* and are also **discarded**
		- Frames that do not fit in the size norms are likely to be the **result** of collisions or other **unwanted signals** and are thus **considered invalid**
- Ethernet MAC address
	- Hexadecimal and the MAC Address
		- An ethernet MAC address consists of a **48-bit** value, expressed using **12 hexadecimal values**
		- **Binary** 00000000 to 11111111 can be represented in **hexadecimal** as the range 00 to FF
		- When using hexadecimal, leading zeroes are always displayed to complete the 8-bit representation. 
			- For example the binary value 0000 1010 is represented in hexadecimal as 0A
			- This is because 8 bits/ a byte is a very common binary grouping method
		- Hexadecimal numbers are often represented by 
			- The value followed by 0x (for example 0x1EB)
			- The hex number followed by an H
			- A subscript 16
	- Ethernet MAC address
		- In an **Ethernet LAN**, **every network device** is connected to the **same** shared media. By using **MAC addressing**, we can **identify** the **different** **devices** at the **data link** (L2) layer
		- A MAC address is 6 bytes in length (48 bits, 12 hexadecimal digits)
		- All MAC addresses must be unique to the ethernet device or ethernet interface.
			- To ensure this, all vendors that sell ethernet devices must register with the IEEE to obtain a unique 6 hexadecimal code called the OUI *(organizationally unique identifier)*. This code is unique to all products that a vendor sells
		- An **ethernet MAC address** is made up of the **6 hexadecimal vendor OUI code** followed by a **6 hexadecimal vendor-assigned value**
	- Frame Processing
		- When a device is forwarding a message to an Ethernet network, the ethernet header includes a **source MAC address** and a **destination MAC address**
		- When a **NIC** receives an **ethernet frame**, it examines the **destination MAC address** to see if it matches its own **physical MAC address** that is stored in RAM. 
			- If there is **no** match, the device discards the frame. 
			- If there is a match, it passes the frame up the OSI layers where the de-encapsulation process takes place.
	- Casting types
		- Different MAC addresses are used for layer 2 unicast, broadcast and multicast communications
		- Unicast MAC Address
			- The process that a source host uses to determine the destination MAC address associated with an **IPv4** address is known as ARP *(Address Resolution Protocol)*
			- The process that a source host uses to determine the destination MAC address associated with an **IPv6** address is known as ND *(Neighbor Discovery)*
		- Broadcast MAC address
			- A **broadcast** frame is received and processed by every device on the **Ethernet LAN**
			- Features
				- Destination MAC address of FF-FF-FF-FF-FF-FF in hexadecimal (48 ones in binary)
				- It is flooded out all ethernet switch ports except the incoming port. **Not** forwarded by a **router**
				- If the encapsulated data is an IPv4 broadcast packet, this means the packet contains a destination IPv4 address that has all ones (1s) in the host portion
		- Multicast MAC address
			- An **ethernet multicast** frame is received and processed by a group of devices that belong to the same **multicast group**
			- Destination MAC address of *01-00-5E* when the encapsulated data is an **IPv4** multicast packet
			- Destination MAC address of *33-33* when the encapsulated data is an **IPv6** multicast packet
			- The multicast is flooded out **all ethernet switch ports** except the incoming port, unless the switch is configured for **multicast snooping**. It is not forwarded by a **router**, unless the router is configured to **route multicast packets**
			- **Multicast addresses** can only be used as a destination of a packet. The **source** will always be a unicast address
- The MAC Address Table
	- Switch fundamentals
		- A layer 2 **ethernet switch** uses layer 2 **MAC addresses** to make **forwarding decisions**. It is completely unaware of the data (protocol) being carried in the data portion of the frame
		- An **ethernet switch** examines its **MAC address table** to make a forwarding decision for each frame
		- When a **switch** is turned on, the **MAC address table** is empty
	- Switch learning and forwarding
		- Examine the source MAC address (learn)
			- Every **frame** that **enters a switch** is checked for **new information** to **learn** and **add to the MAC table**. 
			- It does this by **examining** the **source MAC address** of the frame and the **port number** where the frame entered the switch. 
				- If the **source MAC address** does not exist it is added to the table along with the incoming **port number**
				- If the **source MAC address** does exist the the switch **updates** the **refresh timer** for that entry
			- Most Ethernet **switches** keep an entry in the table for **5 minutes**. After no refresh for 5 minutes the entry is **removed**
			- If the **source MAC address** does exist in the table but on a **different port**, the switch treats this as a **new entry**. The entry is **replaced** using the same MAC address but with the **more current port number** 
		- Find the destination MAC address (forward)
			- If the **destination MAC address** is a unicast address, the switch will look for a **match** between the **destination MAC address** and an entry in its **MAC address table**.
				- If the destination MAC address **is** in the table, it will forward the frame out the **specified port**
				- If the destination MAC address **is not** in the table, it will forward the frame out **all ports** except the incoming port (unknown unicast)
				- If the destination MAC address is a **broadcast** or a **multicast**, the frame is also flooded out **all ports** except the incoming port
	- Filtering Frames
		- As a **switch** receives frames from different devices, it is able to **populate** its **MAC address table** by examining the **source MAC address of every frame**.
		- When the **MAC address table** of the switch contains the **destination MAC address**, it is able to **filter** the frame and **forward** out a **single port** 
- Switch Speeds and Forwarding Methods
	- Frame Forwarding Methods on Cisco Switches
		- Forwarding methods for **switching** data between *network ports*
			- Store-and-forward switching
				- The entire frame is received and the CRC *(Cyclic Redundancy Test)* is computed (test to see for errors in the data). If the CRC is valid, the **switch** looks up the **destination address** which determines the outgoing interface. The frame is then forwarded to the correct port
				- Advantage: **errors** are **detected** **before** the the frame is **copied**, which saves a lot of *bandwidth*
			- Cut-through switching
				- The frame is forwarded before it is entirely received.
				- At minimum, the destination address of the frame must be read before the frame can be forwarded
				- The **switch** reads just enough of the frame to read the *destination MAC address* so that it can determine which port it should forward it to
				- No error checking is performed
				- Types
					- Fast-forward switching
						- Forwards a packet immediately after reading the **destination address** 
						- **Error** prone
						- Destination *NIC* **discards** the **faulty** packet upon receipt
						- **Lowest** level of *latency* (fastest)
					- Fragment-free switching
						- *Switch* performs an **error check** on the **first 64 bytes** of the frame **before forwarding**
							- **Most network errors** and collisions occur during the **first 64 bytes**
	- Memory Buffering on Switches
		- A *switch* may use a **buffering** technique to **store frames** before forwarding them or when the **destination port** is **busy** because of congestion
			- Methods
				- Port-based memory
					- *Frames* are **stored** in **queues** that are **linked** to specific incoming and outgoing **ports**
					- A *frame* is transmitted to the outgoing **port** only when **all frames ahead** in the queue have been **successfully** transmitted
					- **One frame** can **delay** the transmission of **all frames** in memory because of a busy destination port, even when **other frames could be transmitted**
				- Shared memory
					- Deposits **all frames** into a **common** memory *buffer* shared by **all ports**
					- Amount of buffer memory required by a port is dynamically allocated
					- *Frames* in buffer are dynamically **linked to the destination port** enabling a packet to be received on one port and then transmitted on another port **without** moving it to a different queue
						- Only one queue, compared to port based memory where there are two
					- Results in larger frames that can be transmitted with fewer dropped frames 
					- Allows for different data rates on different ports
						- More *bandwidth* can be dedicated to certain ports
		- Most basic settings on switch
			- *Bandwidth* speed
			- *Duplex* settings for each individual switch port
				- Duplex mismatch
					- One of the **most common** causes of **performance issues** on 10-100 Mbps ethernet links. 
					- Occurs when one port on the link operates at *half duplex* while the other port operates at *full duplex*
						- Occurs when one or both ports on a link are **reset**, and the *autonegotiation* process does not result in both link partners having the **same configuration**
						- Also occurs when users reconfigure one side of a link but forget to reconfigure the other.
							- It is best to configure both switch ports at full-duplex
			- These settings must match between the **switch port** and the **connected devices**
			- Auto negotiation
				- Found on most *ethernet switches* and *NICs*
				- Allows two devices to **automatically negotiate** the best *speed* and *duplex capabilities*
				- *Gigabit Ethernet* ports **only** operates in *full-duplex*
