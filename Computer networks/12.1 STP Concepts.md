- Purpose of STP (Spanning Tree Protocol)
	- Loops
		- Ethernet LANs require their topology to be free of loops, so that there is a single path between any two devices
		- In a loop, a data packet is sent through the same series of links in the same order infinitely
		- L2 loops can result in 
			- MAC address table instability
			- Link saturation
			- High CPU utilization on switches and end-devices
			- Network becomes unstable!
		- When multiple paths exist between two devices and there is no STP implementation on the **switches**, a layer 2 loop occurs
		- Loops in L3
			- IPv4 and IPv6 include a mechanism that limits the number of times a L3 device can retransmit a packet
			- A router will decrement the TTL in every IPv4 packet and Hop Limit in every IPv6 packet
			- When these fields are lowered to 0, a router will drop the packet
	- Redundancy
		- Providing multiple paths for traffic so that data can keep flowing even in the event of a failure
		- Redundant paths may cause loops
	- STP (Spanning Tree Protocol)
		- Loop-prevention protocol
		- Allows for a L2 topology that with redundant paths as well as it being free of loops
		- Logically blocks physical loops in a L2 network, preventing frames from circling the network forever
			- Strategically places "blocking-state" ports
			- Dynamically gets unblocked to allow traffic to travel along alternate paths
		- STP compensates for a failure in the network by recalculating and opening up previously blocked ports
		- STP is enabled by default on Cisco switches
	- Broadcast Storm
		- A broadcast storm is when an abnormally high number of broadcasts overwhelms the network during a specific amount of time.
			- Can disable a network within seconds
			- Can be caused by hardware problems such as a faulty NIC or from a L2 loop
		- L2 broadcasts in a network such as ARP requests are very common. L2 multicasts are typically forwarded the same way as a broadcast by the switch. IPv6 packets are never forwarded as a L2 broadcast as ICMPv6 Neighbor Discovery uses L2 multicasts
		- A host caught in a L2 loop is not accessible to other hosts on the network
		- A switch caught in a L2 loop does not know out of which port to forward unicast frames due to the constant changes in its MAC address table
