- Application, Presentation and Session
	- Application Layer
		- Provides the **interface** between **applications** used to **communicate**, and the **underlying network** over which messages are transmitted
		- Application layer protocols
			- HTTP
			- DNS
			- FTS
			- TFTP
			- IMAP
	- Presentation Layer
		- **Formatting** or **presenting** data at the source device into a **compatible** format for **receipt** by **destination device**
		- Compressing and decompressing data
		- Encrypting and decrypting data
	- Session Layer
		- **Creates** and **maintains** (permanent) *dialogs* between *source* and *destination applications*
		- Handles exchange of information to **initiate** dialogs, **keep** them **active** and **restart** sessions
	- TCP/IP Application Layer Protocols
		- *Transmission Control Protocol*
		- Specify format and control information necessary for many common internet communication functions
		- *Application* layer protocols are used by **both** the *source* and *destination* devices during a communication session
		- Application layer protocols that are implemented on the *source* and *destination* host must be **compatible**
		- Commonly used L7 protocols
			- Domain Name System (DNS)
				- Translates domain names into IP addresses
			- Dynamic Host Configuration Protocol (DHCP)
				- Dynamically assigns IP addresses to be re-used when no longer needed
			- Hypertext Transfer Protocol (HTTP)
				- Set of rules for exchanging text, images, sound, video and other multimedia files on the World Wide Web
- Web and Email Protocols
	- Hypertext Transfer Protocol (HTTP)
		- When a web address or *Uniform Resource Locator (URL)* is typed into a web browser, the **web browser** establishes a connection to the **web service**
		- Web page being opened in browser process
			- Step 1
				- Browser interprets three parts of the URL
					- http (protocol or scheme)
					- www.domainname.com (server name)
					- index.html (specific filename requested)
			- Step 2
				- Browser checks with a **name server** to convert the *server name* into a numeric *IP address* which it uses to connect to that server
				- Client initiates an *HTTP request* to a server by sending a *GET request* to the server, asking for the index.html file
			- Step 3
				- In **response** to the **request**, the server sends the *HTML* code for this web page to the **browser**
			- Step 4
				- The **browser** deciphers the *HTML* code and formats the page for the browser window
	- HTTP and HTTPS
		- *Request*/ *response* protocol that **specifies** the message **types** used for that communication
		- Most common message types are
			- GET
				- Client request for data *(HTML pages)*
			- POST
				- Uploads **data files** to the web server such as form data
			- PUT
				- Uploads **resources** or **content** to the web server such as an image
	- Email Protocols
		- Email is a **store-and-forward** method of **sending**, **storing** and **retrieving** messages across a network
		- Messages are **stored** in databases on **mail servers**
		- Email clients communicate with mail servers to **send** and **receive** email
		- Email protocols used for operation
			- Simple Mail Transfer Protocol *(SMTP)*
				- Used to **send** mail
			- Post Office Protocol *(POP)*
				- Used for clients to **receive** mail
	- Simple Mail Protocol (SMTP) 
		- When a client sends email, the **client** *SMTP* process connects with a **server** *SMTP* process on well-known *port 25*
		- **After connection** is made, client attempts to **send** email to server across connection
		- When server **receives** message
			- Local: places message in local account
			- Non-local: forwards message to another mail server
			- If **destination email server** is **unavailable** or **busy**, *SMTP* sets messages to be sent at a **later** time
	- Post Office Protocol (POP)
		- POP is used by an application to **retrieve mail** from a **mail server**
		- When mail is downloaded from server to client using *POP* the messages are **deleted** on server
			- Server **starts** the *POP* service by passively listening on *TCP port 110* for client connection **requests**
			- When a **client** wants to make use of the **service** it sends a request to establish a *TCP* connection with **server**
			- When connection is **established**, POP server sends a **greeting**
			- Client and POP server then exchange **commands** and **responses** until connection is **closed** or **aborted**
	- Internet Message Access Protocol (IMAP)
		- Method to retrieve email messages
		- Copies are downloaded and the original messages are **not deleted**
		- When user decides to **delete** a message, the server synchronizes that action and **deletes** the message from the **server**
- IP Addressing Services
	- Domain Name Service
		- Domain names were created to convert the numeric IP addresses into a simple, recognizable name
		- DNS is an **automated** service that matches **resource names** with the correct **numeric network address**
		- Includes format for *queries*, *responses* and *data*
	- DNS message format
		- Stores many **types** of resource records
			- Name
			- Address
			- Type of record
				- A (end device IPv4 address)
				- NS (authoritative name server)
				- AAAA (end device IPv6 address)
				- MX (mail exchange record)
		- When client makes a **query**, the server *DNS* process looks at its own **records** to resolve the name. If it is **unable** to resolve the name it contacts other servers to resolve the name
		- After a match is **found** and **returned** to the original **requesting** server, the serves temporarily stores the **numbered** address in the event that the same name is requested again
		- Message sections
			- Question
				- The question for the name server
			- Answer
				- Resource Records answering the question
			- Authority
				- Resource Records pointing toward an authority
			- Additional
				- Resource Records holding additional information
	- DNS Hierarchy
		- *DNS* uses a hierarchical system to create a **database** to provide **name resolution**
		- Each *DNS* server maintains a specific **database file** and is responsible for managing *name-to-IP* mappings for that small portion of the entire DNS structure
		- When a *DNS server* receives a request for a name translation that is not within its *DNS zone*, it forwards the request to **another server** with the proper zone for translation
		- Examples of top-level domains
			- .com (business or industry)
			- .org (a non-profit organization)
			- .au (australia)
			- .be (belgium)
	- The nslookup command
		- Computer OS utility that allows user to manually query the DNS servers on the device to resolve a given host name
	- Dynamic Host Configuration Protocol (DHCP)
		- *IPv4*
		- Automates:
			- Assignment of IPv4 addresses
			- Assignment of subnet masks
			- Assignment of gateways
			- Other *IPv4* networking parameters
		- Dynamic addressing
			- In contrast to static addressing, where you enter the IP address information manually
		- When a *host* connects to the *network*, the *DHCP server* is contacted and an address is requested
			- *DHCP server* chooses an address from a configured **range of addresses** called a *pool* and assigns it to its host
		- Many networks use both *DHCP* and *static addressing*
			- DHCP for **general purpose hosts** 
				- Such as end user devices
			- Static addressing used for **network devices**
				- Such as gateway routers, switches, servers and printers
	- DHCP operation
		- Step 1
			- When an *IPv4*, *DHCP-configured* device boots up or **connects to the network**, the client **broadcasts** a *DHCP discover (DHCPDISCOVER)* message to **identify** any **available** *DHCP servers* on the network
		- Step 2
			- A *DHCP server* replies with a *DHCP offer (DHCPOFFER)* message which offers a lease to the client
			- If a client receives **more than one** offer, it must choose **one**
		- Step 3
			- The *client* sends a *DHCP request (DHCPREQUEST)* message that identifies the server and lease offer that the client is accepting
		- Step 4
			- The *server* then returns a *DHCP acknowledgment (DHCPACK)* message that acknowledges to the client that the least has been **finalized**
		- Step 5
			- If the offer is no longer valid, the server responds with a *DHCP negative acknowledgment (DHCPNAK)* message and the process must begin with a new *DHCPDISCOVER* message (step 1) 
- File Sharing Services
	- File Transfer Protocol *(FTP)*
		- FTP was developed to allow for data transfers between a *client* and a *server*
		- A *FTP client* is an application which runs on a computer that is being used to push and pull data from an FTP server
		- Process
			- Step 1
				- The *client* **establishes** the first **connection** to the *server* for **control traffic** using *TCP port 21*
				- Traffic consists of **client commands** and **server replies**
			- Step 2
				- The client establishes the second connection to the server for the actual data transfer using *TCP port 20*
				- This connection is created every time there is data to be transferred
			- Step 3
				- The data transfer can happen in either direction
				- The client can download *(pull)* data from the server, or the client can upload *(push)* data to the server
