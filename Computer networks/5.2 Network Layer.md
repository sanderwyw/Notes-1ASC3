- Network Layer Characteristics
	- Provides **services** to allow end devices to **exchange** data
	- IP version 4 *(IPv4)* and IP version 6 *(IPv6)* are the **principle** network layer communication **protocols**
	- Basic operations
		- Addressing end devices
		- Encapsulation
			- IP encapsulation
				- IP encapsulates the *transport layer (L4)* segment
				- Can use IPv4 or IPv6 and not impact the *L4* segment
				- IP packet will be examined by all *L3* devices as it traverses the network
				- IP address doesn't change from source to destination
					- Except with NAT
						- Having all hosts on a network use the same IP address to communicate outside that network
		- Routing
		- De-encapsulation
	- Characteristics
		- Low overhead
			- Minimal ongoing operational expenses
		- Connectionless
			- IP does **not** establish a **connection** with destination **before sending** packet
			- No control information needed
				- Synchronizations, acknowledgements etc...
			- Destination will **receive** packet when it **arrives**
			- **No pre-notifications** are sent by IP
			- If there is **need** for **connection-oriented traffic**, **another** protocol will handle this
				- Typically *TCP* at L4 
		- Best Effort
			- IP will **not guarantee delivery** of packet
			- **No mechanism** to **resend** data that **isn't received**
			- IP does **not** need **acknowledgments**
			- IP does **not** know if the other device **received** packet
		- Media Independent
			- Unreliable
				- Cannot **manage** of fix **undelivered** or **corrupt** packets
				- Cannot **retransmit** after error
				- Cannot **realign** out of sequence packets
				- **Relies** on **other protocols** for these functions
			- Independent
				- Can be sent over any media type
				- Can be sent regardless of frame type at L2
			- Network layer will establish the MTU *(Maximum Transmission Unit)*
				- Size of **largest** protocol data unit
				- Network receives this from control information sent by the **data link** layer
			- Fragmentation
				- L3 splits the *IPv4* packets into smaller units
				- Fragmenting causes **latency**
				- *IPv6* does **not** fragment packets
- IPv4 Packet
	- Packet Header
		- Purposes
			- Ensures packet is sent in correct direction
			- Contains information for **network** layer **processing** in various fields
			- Information in header is used by **all** layer 3 devices that handle the packet
		- Characteristics
			- Binary
			- Several fields of information
				- Version
					- v4 = 4 bit field (0100)
				- Internet Header Length
				- DS
					- Differentiated services
					- 
				- DSCP
				- ECN
				- Total length
				- Identification
				- Flag
				- Fragment offset
				- Time-to-live
					- Layer 3 hop count. When it becomes zero the router will discard packet
				- Protocol
					- Next level protocol
				- Header Checksum
				- Source IP address
				- Destination IP address
			- Source and destination are most important
- IPv6 Packet
	- Limitations of IPv4
		- IPv4 address depletion
		- Lack of end-to-end connectivity
			- Private addressing and NAT were created to make IPv4 run longer
			- Ended direct communications with public addressing
		- Increased network complexity
			- *NAT* was meant as **temporary** solution but creates **latency** and **troubleshooting** issues
	- Overview
		- *IPv6* overcomes many limitations of *IPv4*
			- Increased address space
				- 128 bit instead of 32 bit
			- Improved packet handling
				- Simplified header with fewer fields
			- Eliminates the need for NAT
				- Since there is a huge amount of addressing, there is no need to use private addressing
				- No private addressing internally
	- Packet Header
		- Simplified but not smaller
		- Header fixed at 40 bytes long
		- Removed fields include
			- Flag
			- Fragment Offset
			- Header Checksum
		- Significant fields
			- Version
			- Traffic class
				- Equivalent to DS
			- Flow label
				- Informs device to handle identical flow labels the same way (20 bit)
			- Payload length
				- Indicates the length of the data portion or payload of packet (16 bit)
			- Next header
				- Next level protocol
			- Hop limit
			- Source address
			- Destination address
		- May also contain extension headers
			- Optional
			- Provide  network layer information
			- Placed between *IPv6* **header** and **payload**
			- Used for *fragmentation*, *security*, *mobility support*, etc.
		- Routers **do not** fragment IPv6 packets
- How a Host Routes
	- Host forwarding decision
		- Packets are created at the **source**
		- Host devices create their own *routing table*
		- Host can send packets to the following
			- Itself
				- 127.0.0.1 (IPv4)
				- ::1 (IPv6)
		- Source device determines whether the destination is local or remote
		- Determination method
			- IPv4
				- Source uses its **own** IP address and subnet mask along with **destination** IP address
				- Compares with own ip
			- IPv6
				- Source uses **network address** and **prefix** advertised by local router
				- Compares with ip of router
	- Default gateway
		- Router or layer 3 switch can be default gateway
		- Features of default gateway
			- Must have IP address in same range as rest of LAN
			- Can accept data from LAN and is capable of forwarding traffic off of the LAN
			- Can route to other networks
		- If a device has **no** default gateway or a **bad** default gateway, its traffic will **not be able to leave** the LAN
	- Process
		- Host will know the default gateway either statically or through DHCP in IPv4
		- IPv6 sends the DGW through RS or can be configured manually
		- DGW is static route which will be last resort route in the routing table
		- All devices on LAN will need DGW of the router
- Introduction to Routing
	- IP Router Routing Table
		- Types of routes in table
			- Directly Connected
				- Automatically added by router, provided interface is active and has addressing
			- Remote
				- Router does not have direct connection
				- May be learned:
					- Manually
						- With static route
					- Dynamically
						- By using routing protocol to have routers share their information with each other
			- Default Route
				- This forwards all traffic to a specific direction when there is no match in the routing table
	- Static Routing
		- Must be configured **manually**
		- Must be adjusted **manually** by the admin when there is change in topology
		 Good for **small** networks
		- Often used in **conjunction** with a **dynamic routing protocol** for configuring a default route
	- Dynamic Routing
		- Dynamic routes automatically
			- Discovers remote networks
			- Maintain up-to-date information
			- Choose the best path to destination
			- Find new best paths when there is topology change
			- Share static default routes with other routers
