- OSI model
	- Meaning
		- Open Systems Interconnection model
		- **Reference model** developed by the International Organization for Standardization
		- Describes **communications** from the **physical implementation** of transmitting bits to the **representation of said data** by a distributed application
		- Most **communication protocols** can be decomposed into the model's **different layers**
	- Layers
		- 1) Physical layer
			- **Lowest** layer
			- **Physical connection** between devices
			- The means of **transmitting** a stream of **raw bits** over a **physical data link** between *network nodes* (communication endpoint)
			- **Electronic circuit** technologies of a **network**
		- 2) Data link layer
		- All communication protocols can be 
			- The means of **transmitting** a stream of **data** within *network nodes* in a local network
			- Considered to be the most complex by some
			- Responsible for *encoding*, *decoding* and *organizing* the outgoing and incoming data
		- 3) Network layer
			- Responsible for *packet forwarding*
			- Responsible for **routing** through intermediate **routers**
		- 4) Transport layer
			- Provides **end-to-end** communication services for applications
		- 5) Session layer
		- 6) Presentation layer
		- 7) Application layer
	- Physical and Logical Topologies
		- The **topology** of a network is the **arrangement and relationship** of the network **devices** and the **interconnections** between them
		- Topology types:
			- Physical topology
				- Shows **physical** connections and how devices are **interconnected**
			- Logical topology
				- Identifies **virtual** connections between devices using **devices interfaces** and **IP addressing schemes**
		- Duplex communication
			- Half-duplex communication *(simplex)* 
				- Only **one** device can **send** or **receive** data **at a time** on a shared medium
				- Used on WLANs and older bus topologies with Ethernet hubs
			- Full-duplex communication
				- **both** devices can **simultaneously** **transmit** and **receive** data **at a time** on a shared medium
				- **Ethernet switches** operate in **full-duplex** mode
		- Access control methods
			- Contention-based access
				- All **nodes** operating in **half-duplex**, competing for use of the medium.
				- CSMA/CD
					- Carrier-sense multiple access
					- Used by legacy Ethernet LANs
					- MAC protocol (medium access control)
					- Operates in **half-duplex** mode where only **one device** sends or receives **at a time**
					- Protocol in which a node **verifies** the **absence of other traffic** before transmitting on a shared transmission medium
					- Collision detection process
						- Devices transmitting **simultaneously** will result in a **signal collision** on the shared media
						- Devices **detect** the **collision**
						- Devices wait a **random** period of time and **retransmit** data
				- CSMA/CA
					- Used by IEEE 802.11 WLANs
					- Operates in half-duplex mode where only one device sends or receives at a time
					- Uses a **collision avoidance process** to **govern** when a device can **send** and **what happens** if **multiple devices send** at the **same time**
					- Collision avoidance process
						- When **transmitting**, devices also **include** the **time duration needed** for the transmission
						- Other devices on the shared medium **receive** the **time duration** information and **know how long** the medium will be **unavailable**
				- Examples:
					- Carrier sense multiple access (CSMA) with collision detection (CD) as used on legacy bus-topology Ethernet
						- Bus network
							- In a **bus network**, each *station* (host) receives all network traffic. and the traffic generated by each *station* has equal transmission priority
					- Carrier sense multiple access (CSMA) with collision avoidance (CA) as used on Wireless LANs
			- Controlled access
				- Deterministic access where **each node** has its **own time** on the medium

- Data Link Layer
	- Use
		- Responsible for **communications** between **end-device NICs** (network interface cards)
		- Allows **upper layer** protocols to access the **physical layer media** 
		- Encapsulates **layer 3 data packets** into **layer 2 data frames**
		- Performs **error detection** and rejects corrupt frames
		- At each step along a path:
			- **Accepts a frame** from the network medium
			- **De-encapsulates** the frame to expose the encapsulated packet
			- **Re-encapsulates** the packet into a **new frame**
			- **Forwards** the **new frame** on the medium of the **next network segment**
	- Data Link Frame
		- **Data** is **encapsulated** by the data link layer with a **header** and **trailer** to form a **frame**
		- A **data link frame** has **three** parts
			- Header
			- Data (contents)
			- Trailer
		- The **fields** of the **header** and **trailer** **vary** according to data link layer protocol
		- The **amount** of **control information** carried with in the frame **varies** according to **access control information** and **logical topology**
		- Frame fields
			- Header
				- Frame start
					- Identifies beginning of frame
				- Addressing
					- Indicates source and destination nodes
					- Also contains NIC address
				- Type
					- Identifies encapsulated layer 3 protocol
				- Control
					- Identifies flow control services
			- Packet
				- Contains the data that should be transferred
			- Trailer
				- Error detection
					- Used to determine transmission errors
				- Frame stop
					- Used to determine transmission errors
		- Layer 2 addresses
			- Also referred to as a physical address
			- Contains which NIC the frame should be sent to
			- Contained in the frame header
			- Used only for **local** **delivery** of a **frame** on the link
			- Updated by each device that forwards the frame
		- LAN and WAN frames
			- The logical topology and physical media determine the data link protocol used
				- Ethernet
				- 802.11 wireless
				- Point to point (PPP)
				- High-level data link control (HDLC)
				- Frame-relay
