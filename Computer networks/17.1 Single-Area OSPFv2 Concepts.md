- OSPF Features and Characteristics
	- Introduction to OSPF
		- OSPF is a link-state routing protocol that works as an alternative to the distance vector Routing Information Protocol (RIP).
			- OSPF has significant advantages over RIP in that it offers faster convergence and scales to much larger network implementations
			- RIP employs a **hop count** as a **routing metric** and **prevents loops** by implementing **limits** on the number of hops allowed on the way to the destination
		- OSPF is a link-state routing protocol that uses the concept of **areas**
			- A network administrator can divide the routing domain into distinct **areas** that help control routing update traffic
		- A **link** can be various things
			- An interface on a router
			- A network segment that connects two routers
			- A stub network such as an Ethernet LAN that is connected to a single router
		- Information about the **state of a link** is known as a **link-state**
			- **Link-state** information includes
				- Network prefix
				- Prefix length
				- Cost
	- Components of OSPF
		- Components
			- All routing protocols share similar components like routing protocol messages to exchange information
				- These messages help build data structures which are then processed using a routing algorithm
			- Routers running OSPF use five types of packets to exchange messages with routing information
				- Hello packet (LSA?)
				- Database description packet
				- Link-state request packet
				- Link-state update packet
				- Link-state acknowledgment packet
			- These packets **discover** neighboring routers and also **exchange** routing information to **maintain accurate information** about the **network**
		- OSPF messages are used to create and maintain three OSPF databases
			- Adjacency Database
				- Table
					- Neighbor Table
				- Description
					- List of all **neighbor routers** to which a router has **established bi-directional communication**
					- Table is **unique** for each router
					- Can be viewed using the *show ip ospf neighbor* command
			- Link-state Database (LSDB)
				- Table
					- Topology Table
				- Description
					- Lists **information** about all other **routers in the network**
					- The database represents the network link-state database
					- All routers within an area have **identical** LSDB
					- Can be viewed using the *show ip ospf database* command
			- Forwarding Database
				- Table
					- Routing Table
				- Description
					- List of routes generated when an algorithm is run on the link-state database
					- Each router's routing table is unique and contains information on how and where to send packets to other routers
					- Can be viewed using the *show ip route* command
		- Router builds the **topology table** using results of **calculations** based on **shortest-path first (SPF)** algorithm
			- SPF algorithm is based on the **cumulative cost** to **reach a destination**
		- **SPF tree** is created by 
			- The **SPF** algorithm puts each **router** at the **root of the tree**
			- The SPF algorithm calculates the **shortest path** to each node
			- The **SPF tree** is then used to calculate the best routes
			- **OSPF** places the best routes into the **forwarding database,** which is used to make the **routing table**
	- Single-Area and Multiarea OSPF
		- To make OSPF more **efficient** and **scalable**, OSPF supports **hierarchical routing** using **areas**
		- An OSPF area is a **group of routers** that share the same **link-state information** in their **LSDBs**
		- OSPF can be implemented in one of two ways
			- Single-Area OSPF
				- All routers are in **one area**
				- Best practice is to use **area 0**
			- Multiarea OSPF
				- OSPF is implemented using **multiple areas** in a **hierarchical fashion**
				- All areas must connect to the backbone area **(area 0)** 
				- Routers **interconnecting** the **areas** are referred to as **Area Border Routers**
- OSPF Operation
	- Establishing Neighbor Adjacencies
		- Routers use the following process to establish adjacency on a multicast network
			- 1. Down to Init State
				- When OSPFv2 is enabled on the interface:
					- **R1** transitions from **Down** to **Init**
					- **R1** starts sending OSPFv2 **Hellos** out of the interface in an attempt to **discover neighbors**
			- 2. Init State
				- When **R2** receives a hello from the previously unknown router R1:
					- **R2** adds **R1**'s **router ID** to the **neighbor list**
					- **R2** responds with a **Hello** packet containing its own router ID
			- 3. Two-Way State
				- **R1** receives **R2**'s hello
				- **R1*** notices that the message contains the **R1 router ID** in the list of **R2's neighbors**
				- **R1** adds **R2's router ID** to the **neighbor list** and transitions to the **Two-Way State**
				- If **R1** and **R2** are connected with a **point-to-point link**, they transition to **ExStart**
				- If **R1** and **R2** are connected over a **common Ethernet network**, the **DR/BDR** election occurs
			- 4. Elect the DR (Designated Router) and BDR (Backup Designated Router)
				- The DR and BDR election occurs, where the router with the highest router ID/ highest priority/ highest in the hierarchy is **elected as the DR**, and **second highest** as the **BDR**
		- The Need for a DR (Designated Router)
			- Multiaccess networks can create two challenges of OSPF regarding the flooding of LSAs/ hello messages, as follows
				- Creation of multiple adjacencies
					- Ethernet networks could potentially **interconnect** many **OSPF routers** over a **common link**
					- Creating adjacencies with every router would lead to an excessive number of LSAs/ hellos exchanged between routers on the same network
				- Extensive flooding of LSAs
					- Link-state routers **flood their LSAs** any time OSPF if **initialized** or when there is a **change in topology**
		- LSA Flooding with a DR
			- An **increase** in the **number of routers** on a **multiaccess network** also increases the **number of LSAs** exchanged between the routers
			- If **every router** in a multiaccess network had to **flood** and **acknowledge** all **received LSAs** to all other routers on that same multiaccess network, the network traffic would become quite **chaotic**
			- On multiaccess networks, OSPF elects a DR to be the collection and distribution point for LSAs sent and received. A BDR is also elected in case the DR fails
				- All other routers become DROTHERs
				- A DHROTHER is a router that is neither the DR nor the BDR
