- Dynamic NAT
	- Scenario
		- Dynamic NAT **automatically** maps **inside local addresses** to **inside global addresses**
		- Dynamic NAT uses a **pool** of **inside global addresses**
		- Pool of inside global addresses is available to **any device** on the **inside network** on a **first-come first-served basis**
		- If **all** addresses in the pool are in use, a device must **wait** for an available address before it can access the outside network
	- Configuring Dynamic NAT
		- Use *ip nat pool (name) (addresses)* to define the pool of addresses that will be used for translation
		- Configure a standard ACL to identify (permit) only those addresses that are to be translated
			- *access-list (number) permit (address) (mask)*
		- Use *ip nat inside source list (number) pool (name)*  to bind the ACL to the pool
		- Use *ip nat inside* to specify which interfaces are inside after navigating to them with *interface serial 0/1/0*
		- Use *ip nat outside* to specify which interfaces are outside after navigating to them with *interface serial 0/1/0*
	- Analyzing Dynamic NAT
		- Dynamic NAT translation process (Inside to Outside)
			- 1.
				- PC1 and PC2 send packets requesting a connection to the server
			- 2.
				- R2 receives the first packet from PC1
				- R2 checks the ALC to determine if the packet should be translated
				- R2 selects an available global address
				- R2 creates a translation entry in the NAT table
			- 3.
				- R2 replaces the inside local source address of PC1 *(192.168.10.10)* with the translated inside global address of *(209.165.200.226)*
				- R2 forwards the packet
		- Dynamic NAT translation process (Outside to Inside)
			- 4.
				- Server receives the packet from PC1 and responds using the destination address of *209.165.200.226*
				- The server receives the packet from PC2
			- 5
				- 1
					- When R2 receives the packet with the destination address of 209.165.200.226; it performs a NAT table lookup
					- R2 translates the address back to the inside local address
					- R2 forwards the packet towards PC1
				- 2
					- When R2 receives the packet with the destination address of 209.165.200.227; it performs a NAT table lookup
					- R2 translates the address back to the inside local address 192.168.11.10 
					- R2 forwards the packet toward PC2
			- 6
				- PC1 and PC2 receive the packets and continue the conversation
				- The router performs steps 2 to 5 for each packet
	- Verifying Dynamic NAT
		- *show ip nat translations* displays all static translations that have been configured and any dynamic translations that have been created by traffic
		- Translation entries time out after 24 hours unless the timers have been reconfigured with the *ip translation timeout (timeout-seconds)* command in global config
		- Use *clear ip nat translation* in privileged EXEC mode to clear dynamic entries before the timeout has expired
		- Use *show ip nat statistics* to display information about
			- Total numbers of active translations
			- NAT configuration parameters
			- Number of addresses in the pool
			- How many addresses have been allocated
