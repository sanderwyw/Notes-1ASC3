- EtherChannel Operation
	- Link Aggregation
		- Sometimes more bandwidth between devices is needed than what can be provided with a single link
			- Multiple links could be connected between devices to increase bandwidth
			- However, STP will block redundant links to prevent switching loops
		- EtherChannel allows redundant links between devices that will thus not be blocked by STP
		- EtherChannel groups multiple physical Ethernet links together into one single logical link
			- Can be used to provide 
				- Fault-tolerance
				- Load sharing
				- Increased bandwidth
				- Redundancy between switches, routers and servers
		- EtherChannel makes it possible to combine the number of physical links between the switches to increase the overall speed of switch-to-switch communication
	- EtherChannel
		- When an EtherChannel is configured, the resulting virtual interface is called a port channel
		- The physical interfaces are bundled together into a port channel interface
	- Advantages of EtherChannel
		- Configuration tasks can be done on the EtherChannel interface instead of on each individual port, ensuring consistency while configuring links
		- EtherChannel relies on existing switch ports, so you don't have to upgrade the link to a faster connection to have more bandwidth
		- Load balancing takes place between links that are part of the same EtherChannel
		- STP sees EtherChannel as one logical link
			- EtherChannel creates an aggregation that is seen as one logical link. When several EtherChannel bundles exist between two switches, STP may block one of the bundles to prevent switching loops. When STP blocks one of the redundant links, it blocks the entire EtherChannel. This blocks all the ports belonging to that EtherChannel link. Where there is only one EtherChannel link, all physical links in the EtherChannel are active because STP sees only one (logical) link
		- EtherChannel provides redundancy 
			- The overall link is seen as one logical connection
			- The loss of one physical link within the channel does not create a change in the topology
	- LACP Operation
		- LACP allows several physical ports to be bundled to form a single logical channel
		- Allows a switch to to negotiate with another switch by sending LACP packets to the other switch
		- Works similar to Cisco EtherChannel but can be used to provide EtherChannel in multivendor environment
			- Both protocols are supported on Cisco
		- LACP is part of an IEEE (Institute of Electrical and Electronics Engineers) specification
		- Creates an EtherChannel link by detecting the configuration of each side and making sure they are compatible so the link can be enabled when needed
		- Has different modes
			- On
				- Forces the interfaces to channel without LACP
				- Interfaces configured in the On mode do not exchange LACP packets
			- LACP active
				- Places a port in an active negotiating state, in which it initiates negotiations with other ports by sending LACP packets
			- LACP passive
				- Places a port in a possible negotiating state, in which it responds to the LACP packets that it receives but does not initiate LACP packet negotiation
		- Example
			- On - On = Channel established
			- On - Active/Passive = No Channel established **(((?)))**

- Configuring EtherChannel
	- LACP Configuration
		- Specify the interfaces that compose the EtherChannel group using the *interface range (interface)* global configuration mode command
			- The *range* keyword allows you to select several interfaces and configure them all together
		- Create the port channel with the *channel-group (identifier) mode active* command, followed by the interface identifier
			- The *mode active* keywords identify this as an LACP EtherChannel configuration
		- To change L2 settings on the port channel interface, enter port channel configuration mode using the *interface port-channel* command, followed by the interface identifier
			- A following command could be *switchport mode trunk* and then *switchport trunk allowed vlan (vlans)* to turn the logical channel into a trunk
- Verifying and Troubleshooting EtherChannel
	- *show interfaces port-channel* displays the general status of the port channel interface
	- *show etherchannel summary* displays one line of information per port channel
	- *show etherchannel port-channel* displays information about a specific port channel interface
	- *show interfaces etherchannel* can provide information about the role of a physical member interface of the EtherChannel
