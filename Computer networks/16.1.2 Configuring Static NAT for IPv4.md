- Static NAT
	- Scenario
		- Static NAT is a one-to-one mapping between an inside address and an outside address
		- Allows external devices to initiate connections to internal devices using the statically assigned public address
		- An internal web server may be mapped to a specific inside global address so that it is accessible from outside networks
	- Configuring Static NAT
		- Use *ip nat inside source static* to create a **mapping** between the **inside local address** and the **inside global addresses**
		- Use either *ip nat inside* or *ip nat outside* depending on whether you want to configure the interfaces participating in the translation as inside or outside relative to NAT
	- Analyzing Static NAT
		- **Client** sends a packet to the web server
		- **R2** receives packets from the client on its NAT outside interface and checks its NAT table
		- **R2** translates the inside global address of to the inside local address and forwards the packet towards the web server
		- **Web server** receives the packet and responds to the client using its inside local address
		- **R2** receives the packet from the web server on its NAT inside interface with source address of the inside local address of the web server and
		- **R2** translates the source address to the inside global address
	- Verifying Static NAT
		- Use *show ip nat translations* to verify NAT operation
			- If the case is a static NAT configuration, the translation will always be present in the NAT table regardless of any active communications
			- If the command is issued during an active session, the output also indicates the address of the outside device
		- Use *show ip nat statistics*
			- Displays information about 
				- The total number of translations
				- NAT configuration parameters
				- The number of addresses in the pool
				- The number of addresses that have been allocated
		- Use *clear ip nat statistics* before verifying, as it is best to clear statistics from any past translations
