- Important Terms
	- Data
		- Refers to specific *facts* that are take the form of *digits*, *numbers*, *words*, *characters*
		- Sorts
			- Digits
			- Numbers
			- Words
			- Characters
			- Photos
			- Video Footage
			- Audio Clips
	- Information
		- Refers to the *meaning* that users assign to *facts* and the *connections* that are made between those facts
	- DBMS
		- = Database Management System
			- The software that manages a database
			- Collection of *data* in the context of an *IT application*
		- Data is stored *persistently*
			- Does not disappear after powering off
			- Most IT applications need permanent storage
			- *Databases* are the typical *solution* for storing *persistent* data
		- Client-server software
			- Server = DBMS
			- Client = User of database
			- Language = SQL (for when client and server speak to eachother)
		- Advantages
			- *Multiple* users at the *same time*
			- Safeguarding *consistency*/ minimal *redundancy*
			- *Standardised* language for querying data (SQL)
			- *Security*; each user has certain *privileges*
	- From Model to SQL
		- The Point of Modelling
			- Think first, then do
				- Clarify what is going to be done before the project is started
			- Clearer overview
				- How much work will the project be/ what is needed for it
			- Fewer mistakes
				- Has already been thought through
			- Quality control
				- Documentation (for maintenance/ extensions)
		- The What of Modelling
			- We need the *data* that we want to put into the database
		- The How of Modelling
			- 3 steps
				- Conceptual model
				- Logical model
				- Physical model
	- Three model layers
		- A data model is built up of *3* layers
			- Conceptual data model
				- Which *information* do we need to *include* in our *database*
			- Logical data model
				- How should we *structure* the *data* according to our chosen *database* model
			- Physical data model
				- How should we *describe* the data struture according to our hosen DBMS
