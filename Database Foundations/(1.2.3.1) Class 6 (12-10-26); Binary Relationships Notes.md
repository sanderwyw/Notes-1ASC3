- Relationships
	- Describe how entity types are connected to each other
	- Degrees of a relationship
		- 1 entity type with itself: *unary*
		- 2 entity types with each other: *binary* (focus of this document)
	- Notation in ERD
		- Diamond
		- Name starts with capital letter
		- Verb or expression of possession
			- Buys, Is part of...
- Cardinality
	- Minimum cardinality
		- (**x**, y)
		- Can an entity of this type exist without taking part in the relationship?
			- Yes -> **0**
			- No -> **1**
	- Maximum cardinality
		- (x, **y**)
		- Can an entity of this type take part in the relationship several times at once?
			- Yes -> **N**
			- No -> **1**
			- Other options: M, O, P...
- Types of relationships
	- 1-1 relationship
		- Maximum cardinality = 1 for *both* entity types
			- (0, **1**) -> (1, **1**)
		- Every entity in entity type *1* has exactly *one* counterpart in entity type *2*
			- Ex. ID cards and people
	- 1-N relationship
		- One-to-many relationship
		- Maximum cardinality = **1** for *one* of the entity types, **N** for the *other*
		- An entity in entity type *1* can have *multiple* counterparts in entity type *2*
	- N-M relationship
		- Many-to-many relationship
		- Maximum cardinality: 'N' for one entity type, 'M' for the other
			- (1, **N**) -> (1, **M**) instead of (1, **N**) -> (1, **N**)
		- 'N', 'M', 'O' are used to indicate a maximum cardinality of 'many' more than once within the same relationship
- Relationship attributes
	- Not possible with 1-1 or 1-N relationship
		- In these cases attributes should only be assigned to the entity types
	- Only possible with N-M relationship
		- Attributes assigned to the relationship itself, not an entity type
- Redundancy
	- Redundancy = adding relationships that can be derived from other relationships
	- This creates unnecessary complexity and increases risk of errors
