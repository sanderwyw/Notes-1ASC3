- Cartesian product
	- Multiplying a row by a column results in a cartesian product
		- Resulting numbers and column = # of entries is table A times # of entries in table B
		- Cartesian product for RIGHT OUTER JOIN and LEFT OUTER JOIN is *not* commutative
	- Example
		- A [x, y, z] * B [1, 2, 3] = AB [(x,1) , (x,2) , (x,3) , (y,1) , (y,2) , (y,3) , (z,1) , (z,2) , (z,3)]
	- SQL
		- Simply typing **SELECT * FROM tableA, tableB** will result in the cartesian product of tableA and tableB
- INNER JOIN
	- By using **SELECT * FROM tableA, tableB WHERE tableA.id = tableB.id** the cartesian product of tableA and tableB will be made, but only the rows where there is a match between the two given ids (or other value)
	- Graphical representation
		- INNER JOIN
			- Only shows rows of A * B that are a match
		- LEFT OUTER JOIN
			- Shows results of A * B, as well as all contents of A
			- Contents of B that have no match with A will return as NULL 
		- RIGHT OUTER JOIN
			- Shows results of A * B, as well as all contents of B
			- Contents of A that have no match with B will return as NULL
		- FULL OUTER JOIN/ FULL JOIN
			- Shows results of A * B, as well as 
			- If a row in A has no match in B, the result set includes the row's data and NULL values for all column of B (and vice versa)
	- JOIN conditions/ ON
		- These conditions are also referred to as *foreign keys*
- Implicit vs Explicit Joins
	- The JOIN function can be simulated with **SELECT * FROM tableA, tableB**, although this is far less clear and does not make distinction between INNER and OUTER JOIN
	- Always use explicit JOIN instead of implicit JOIN
- Combining several joins
	- JOIN can be used several times in one query
	- This needs to happen for (N-M) relationships, where there is a junction table
	- When doing this, it is highly advised to use aliases
		- **FROM tableA A** (where A is the alias for table A) **INNER JOIN tableB B** (where B is the alias for table B)
